# IwaC

Cコンパイラのサブセットを自作するプロジェクト。

最終的なゴールは KosabaOS（自作OS）のプロジェクトと接続している:
OS上のシェルからコンパイラを実行して Hello World をコンパイルし、
実行できるようにすること。そのコンパイラが、この `iwac`。

欲張らない方針で進める。プリプロセッサなどは対象外
（計画は `doc/roadmap.md`、設計は `doc/design.md`、
できたことは `doc/progress.md`、決めたことは `doc/notes.md`）。

ここまでの歩み（v0〜v4）を図で説明したページもある:
[`doc/phases.html`](doc/phases.html)（単体で開ける HTML、
初心者向けに各フェーズで何をやったかを解説）。
第3層（機械語への変換）を読むための RISC-V の前提知識は
[`doc/riscv-basics.md`](doc/riscv-basics.md) にまとめた
（命令の区画、即値で値を運ぶ仕組み、レジスタに乗る値）。

## 現在地: v29（入口・出口の約束への移行）

v29 では KosabaOS の新しい入口・出口の約束に
生成コードを合わせた。exec で引数が渡せるように
なった OS（入口で a0 = argc、a1 = argv）に対し、
生成コードはレジスタをそのまま main へ渡し、
v22 の決め打ち argv と静的領域は廃止した。起動は
`run iwac.elf --kosaba hello.c` の形になる。
あわせて main の戻り値を exit の終了ステータス
として返す（ドライバが前の段の成否を見られる）。
固定点は新しい OS で再確認済み（第2世代も一致）。

その前の v28 では出力の節約をした。KosabaOS 用
ELF を PT_LOAD 3本に分け、ゼロだけの配列領域を
ファイルに含めない（BSS）形にして、iwac2.elf は
約3.0MB から 126,893 バイトになった。メモリ上の
大きさは変わらない。

その前の v27 で、iwac が iwac 自身をコンパイル
できるようにする階段（v16〜v27、計画は
doc/roadmap.md と doc/selfhost.md）を登り切った。
12段目（最終段）はセルフコンパイル: 組み込み
`syscall3` と、外部4関数を iwac の言語で実装した
`kosaba/kosaba_rt.c` を足し、ホスト版 iwac が作った
iwac2.elf が KosabaOS 上で同じ入力から作る iwac3.elf
とバイト単位で一致した（固定点。第2世代も一致）。
iwac2 が OS 上で Hello World をコンパイル・実行
できることも確認済み。セルフコンパイルの過程では
実物の不具合が5件出て直した（前処理の文字リテラル、
条件分岐の距離の緩和、大きな定数の作り方、`*p` の
読み書きの幅、値の表現の一貫性。詳細は
doc/selfhost.md の v27 の節）。
11段目は配列のスコープとローカル配列: 配列の名簿に
持ち主（関数）を持たせ、名前の解決を変数と同じ作法
にした。関数の中で宣言した配列は、その関数の
フレームに置かれる（再帰でも呼び出しごとに別の実体）。
iwac 自身のソースは全文が読めるようになり、残る壁は
外部の4関数（write / open / read / close）の定義だけ
になった（次段 v27 の kosaba_rt.c が埋める）。
10段目は容量の調整と小さい構文の追随: 計測版で
iwac 自身のソースを実測（ノード 10,951、命令
26,233、変数 513、関数 99）し、表の定数を育てた
（ノード 16384、命令 32768、変数 1024、関数 128、
ソース上限 約256KB）。あわせて iwac 自身のソースが
使う形へ言語を追随させた（`static`、引数8つ、三項
演算子、キャスト、複合代入、要素への `++` / `--`、
単一文の本体など）。コンパイルされた iwac の静的
データは約2.9MB になるため、KosabaOS のデータ領域
（2MB）の拡張を OS 側と相談し、virt は 4MB 化
（K210 でのセルフホストは目標にしない）と決定した
（OS 側の 4MB 化の実装も完了済み）。
9段目はグローバル宣言とプロトタイプ: ファイル範囲の
変数宣言が `main` と混在できるようになり、初期化子
（定数だけ）は静的領域の初期イメージとして埋まる。
関数の宣言だけ（プロトタイプ）を先に書けるように
なり、相互再帰が書ける。あわせて KosabaOS 用 ELF を
コード（R+X）とデータ（0x40200000、R+W）の2セグメント
に分け、OS 上で静的データに書けるようになった
（main の argc/argv とグローバル書き込みの OS 実走
確認も完了）。
8段目は配列の完成: 要素の大きさが型で決まる（char は
1バイト、それ以外は 8バイト）ようになり、2次元配列と
ポインタの添字（`argv[i]` が 8 バイト歩幅で読める）が
使える。
7段目は関数の完成: 引数は4つまで（a0〜a3）、戻り値が
あり、呼び出しが式になった（`x = fib(n-1) + fib(n-2);`
のような再帰がそのまま書ける）。`main` も引数を持てる
ようになり、KosabaOS 向けでは決め打ちの argv が渡る。
6段目は変数のメモリ化: 変数は全部メモリに住むように
なり（レジスタ時代の「4個まで」が消えた）、スコープは
関数単位になった。宣言の文（`int i;` / `int i = 0;`）、
for の宣言つき初期化、単項 `&`（住所）も使える。
5段目（v20）は制御構文の完成: `for`、`break`、
`continue`、値なしの早期 `return`。
1段目（v16）は字句の完成: C 形式のブロックコメント、
文字リテラル（`'A'`、`'\n'`、`'\0'`）、型の語彙の拡張
（long / unsigned / signed / short）。

その下の土台（v15）:

iwac 本体が KosabaOS のユーザープログラムとして動く
ようになった（`kosaba/build-kosaba.sh` で `iwac.elf` を
ビルド）。データ領域が 1MB 級のボード（K210）向けには、
容量を絞った小容量版「shirasu」もある
（`kosaba/build-shirasu.sh` で `iwac-shirasu.elf`、
静的データ約255KB）。iwac.c は無変更で、入口（crt）と4つの外部関数の
実装（OS のシステムコール）を横に置いて差し替えた。
OS のシェルで:

```
kosaba> run iwac.elf --kosaba hello.c     (hello.c → hello.elf が作られる)
kosaba> run hello.elf
Hello, World!
```

までを、OS 本線（データ領域対応済み）での統合検証で
確認済み（詳細は doc/progress.md）。

その下の土台（v14）:

出力ターゲットに KosabaOS が増えた:

```
iwac --kosaba hello-kosaba.c > hello.elf
```

OS の ELF ローダに載る ELF（配置 0x40000000）を出し、
出力は putc システムコール、終わりは exit システム
コールになる。同梱の `examples/hello-kosaba.c` を
OS のスクラッチコピーで統合検証済み: シェルから
`run` で実行して `Hello, World!` が出て、プロンプトに
戻ることを確認した。

その下の土台（v13 まで）:

単純な `#define` が入った。`#define THRE 32` のように
定数に名前が付けられる（単語単位の置き換えだけ。
文字列とコメントの中は置き換えない、入れ子は展開
しない、再定義はエラー。`#include` は対象外のまま）。
iwac 自身のソースは今もプリプロセッサ無しで書く。

その下の土台（v12 まで）:

`main` の形が入った。`int main() { ... }` と書くと、
そこがプログラムの入口になる（`examples/hello.c` も
この形）。main が無ければ従来の形もそのまま動く。
main があるのに外側に文を書く混ぜ書きはエラー。

その下の土台（v11 まで）:

関係演算子 `<` `>` `<=` `>=` が入った（優先順位は
C の段: 足し算よりゆるく `==` より固い）。ループの条件が
`while (i < 10)` と自然に書ける。

その下の土台（v10 まで）:

入力がファイルから読めるようになった:

```
iwac hello.c > hello.bin
```

同梱の `examples/hello.c` が、まさにその形でコンパイル
できて QEMU で `Hello, World!` を出す。ファイルの中身の
ために改行と行コメント `//` も読めるようになった。
従来の引数に直接書く形も残してある。

その下の土台（v9 まで）:

配列が入った。宣言は `char buf[16];` の形で、要素は
1バイト。置き場所はレジスタでなくメモリ（コード＋文字列の
後ろの静的な領域）で、配列の名前そのものの値は先頭
アドレスだから、関数へ渡したりポインタ変数に入れたり
できる。要素の読み書きは `buf[i]` / `buf[i] = 値;`。

その下の土台（v8 まで）:

条件分岐 `if` / `else` が入った（本体は `while` と同じく
`{ }` で囲む形。`else if` の連なりと、関数や `while` の
中での使用も可）。制御構造は `while` と `if` の2つになった。

その下の土台（v7 まで）:

演算子の優先順位が C と同じ順になった（固い順に:
ポインタ読みとかっこ、`*` `/`、`+` `-`、`==` `!=`、`&`）。
かっこも使えるので、ポーリングは C と同じく
`((*0x10000005 & 32) == 0)` と書く。両側が式になる計算
（`(50 + 10) * (1 + 1)` など）は、左の結果をスタックへ
退避して評価する（必要なプログラムでのみ用意される）。

その下の土台（v6 まで）:

- 絶対アドレスの読み書き: `*0x10000005`（状態レジスタ LSR を
  読む）、`*0x10000000 = c;`（送信窓口 THR へ書く）。住所は
  16進数で書き、材料は auipc 相対で作るので壊れない
- ビット演算 `&`、空の本体の `while`、
  ポインタ変数経由の書き込み `*p = 値;`
- 本物の `void uart_putc(char c) { while ((*0x10000005 & 32) == 0)
  { } *0x10000000 = c; }` と `uart_puts` を組み合わせた
  プログラムがコンパイルでき、実行すると文字列が出る。
  組み込みの `putc` は互換のため残してある

その下の土台（v5 まで）:

- プログラムは、関数定義と文の並びに任意で最後の式を続けた
  もの。文は代入文、`putc(式);`、`while (式) { 文の並び }`、
  関数の呼び出し。式には比較 `==` / `!=` も入った
  項に使える数字は 0..2047、変数は最大4個（レジスタに割り当て）
- 関数定義は `void 名前(char *s) { ... }` の形（型は読み捨て、
  引数は1つまで、戻り値は無し）。引数は `a0` で渡し、戻り先は
  スタックに退避するので、関数が関数を呼ぶこともできる
- KosabaOS の print loop そのもの
  `void uart_puts(char *s) { while (*s != 0) { putc(*s); s = s + 1; } }`
  に呼び出し側を付けたプログラムがコンパイルでき、
  実行すると文字列が出る
- 目下の目標は、KosabaOS の print loop（`uart_puts`）を
  コンパイルできるように育てること（計画は `doc/roadmap.md`）
- `iwac` は、実行時にプログラムを計算して最後の式の値の下1バイトを
  UART に出し、止まる RISC-V (rv64i) の生バイナリを標準出力に
  書き出す（`65` だけなら16バイト、文や項が増えると少しずつ育つ）
- 出力バイナリは QEMU virt で `-kernel` に渡すと、OpenSBI が
  `0x80200000` に置いて実行する（KosabaOS と同じ土俵）

## ビルドと実行

ビルド（ホストの gcc で）:

```sh
./build.sh
```

本体は `src/` の7断片（01-head.c 〜 07-main.c）に分かれて
いて、build.sh が番号順に連結した `iwac_all.c` を gcc で
コンパイルする（`#include` を使わない約束のための形。
手でやるなら `cat src/0*.c > iwac_all.c` してから
`gcc -std=c11 -Wall -Wextra -O2 -o iwac iwac_all.c`）。

コンパイルと実行:

```sh
./iwac examples/hello.c > hello.bin   # ファイルから読む (v10〜)
qemu-system-riscv64 -machine virt -bios default -kernel hello.bin \
    -m 128M -nographic  # シリアルに Hello, World! と出る

./iwac '65+1' > a.bin   # 従来の形 (引数そのものをコンパイル)
qemu-system-riscv64 -machine virt -bios default -kernel a.bin \
    -m 128M -nographic  # シリアルに B と出て止まる (終了は Ctrl-A x)
```

まとめて確認する検証スクリプトもある:

```sh
./test.sh
```

環境の作り方（ツールの種類・バージョン・入手方法）は
`doc/environment.md` にメモしてある。ツール本体はこのリポジトリには
入れず、手元ディスクの別ディレクトリに置く。

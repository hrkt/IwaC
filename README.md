# IwaC

Cコンパイラのサブセットを自作するプロジェクト。

最終的なゴールは KosabaOS（自作OS）のプロジェクトと接続している:
OS上のシェルからコンパイラを実行して Hello World をコンパイルし、
実行できるようにすること。そのコンパイラが、この `iwac`。

欲張らない方針で進める。プリプロセッサなどは対象外
（計画は `doc/roadmap.md`、設計は `doc/design.md`、
できたことは `doc/progress.md`、決めたことは `doc/notes.md`）。

ここまでの歩み（v0〜v4）を図で説明したページもある:
[`doc/phases.html`](doc/phases.html)（単体で開ける HTML、
初心者向けに各フェーズで何をやったかを解説）。

## 現在地: v18（セルフホストへの階段の3段目）

iwac が iwac 自身をコンパイルできるようにする階段
（v16〜v26、計画は doc/roadmap.md と doc/selfhost.md）を
登っている。
3段目は条件付きコンパイル: `#ifdef` / `#ifndef` /
`#else` / `#endif` が前処理で使える。定義済みマクロ
`__IWAC__` と `__KOSABA__`（--kosaba のとき）で、
1つのソースをターゲット別に切り替えられる。
2段目（v17）は複数ファイル入力: `iwac a.c b.c` と
並べると順につないで1つのソースとして読む。
1段目（v16）は字句の完成: C 形式のブロックコメント、
文字リテラル（`'A'`、`'\n'`、`'\0'`）、型の語彙の拡張
（long / unsigned / signed / short）。

その下の土台（v15）:

iwac 本体が KosabaOS のユーザープログラムとして動く
ようになった（`kosaba/build-kosaba.sh` で `iwac.elf` を
ビルド）。iwac.c は無変更で、入口（crt）と4つの外部関数の
実装（OS のシステムコール）を横に置いて差し替えた。
OS のシェルで:

```
kosaba> run iwac.elf     (hello.c → hello.elf が作られる)
kosaba> run hello.elf
Hello, World!
```

までを、OS 本線（データ領域対応済み）での統合検証で
確認済み（詳細は doc/progress.md）。

その下の土台（v14）:

出力ターゲットに KosabaOS が増えた:

```
iwac --kosaba hello-kosaba.c > hello.elf
```

OS の ELF ローダに載る ELF（配置 0x40000000）を出し、
出力は putc システムコール、終わりは exit システム
コールになる。同梱の `examples/hello-kosaba.c` を
OS のスクラッチコピーで統合検証済み: シェルから
`run` で実行して `Hello, World!` が出て、プロンプトに
戻ることを確認した。

その下の土台（v13 まで）:

単純な `#define` が入った。`#define THRE 32` のように
定数に名前が付けられる（単語単位の置き換えだけ。
文字列とコメントの中は置き換えない、入れ子は展開
しない、再定義はエラー。`#include` は対象外のまま）。
iwac 自身のソースは今もプリプロセッサ無しで書く。

その下の土台（v12 まで）:

`main` の形が入った。`int main() { ... }` と書くと、
そこがプログラムの入口になる（`examples/hello.c` も
この形）。main が無ければ従来の形もそのまま動く。
main があるのに外側に文を書く混ぜ書きはエラー。

その下の土台（v11 まで）:

関係演算子 `<` `>` `<=` `>=` が入った（優先順位は
C の段: 足し算よりゆるく `==` より固い）。ループの条件が
`while (i < 10)` と自然に書ける。

その下の土台（v10 まで）:

入力がファイルから読めるようになった:

```
iwac hello.c > hello.bin
```

同梱の `examples/hello.c` が、まさにその形でコンパイル
できて QEMU で `Hello, World!` を出す。ファイルの中身の
ために改行と行コメント `//` も読めるようになった。
従来の引数に直接書く形も残してある。

その下の土台（v9 まで）:

配列が入った。宣言は `char buf[16];` の形で、要素は
1バイト。置き場所はレジスタでなくメモリ（コード＋文字列の
後ろの静的な領域）で、配列の名前そのものの値は先頭
アドレスだから、関数へ渡したりポインタ変数に入れたり
できる。要素の読み書きは `buf[i]` / `buf[i] = 値;`。

その下の土台（v8 まで）:

条件分岐 `if` / `else` が入った（本体は `while` と同じく
`{ }` で囲む形。`else if` の連なりと、関数や `while` の
中での使用も可）。制御構造は `while` と `if` の2つになった。

その下の土台（v7 まで）:

演算子の優先順位が C と同じ順になった（固い順に:
ポインタ読みとかっこ、`*` `/`、`+` `-`、`==` `!=`、`&`）。
かっこも使えるので、ポーリングは C と同じく
`((*0x10000005 & 32) == 0)` と書く。両側が式になる計算
（`(50 + 10) * (1 + 1)` など）は、左の結果をスタックへ
退避して評価する（必要なプログラムでのみ用意される）。

その下の土台（v6 まで）:

- 絶対アドレスの読み書き: `*0x10000005`（状態レジスタ LSR を
  読む）、`*0x10000000 = c;`（送信窓口 THR へ書く）。住所は
  16進数で書き、材料は auipc 相対で作るので壊れない
- ビット演算 `&`、空の本体の `while`、
  ポインタ変数経由の書き込み `*p = 値;`
- 本物の `void uart_putc(char c) { while ((*0x10000005 & 32) == 0)
  { } *0x10000000 = c; }` と `uart_puts` を組み合わせた
  プログラムがコンパイルでき、実行すると文字列が出る。
  組み込みの `putc` は互換のため残してある

その下の土台（v5 まで）:

- プログラムは、関数定義と文の並びに任意で最後の式を続けた
  もの。文は代入文、`putc(式);`、`while (式) { 文の並び }`、
  関数の呼び出し。式には比較 `==` / `!=` も入った
  項に使える数字は 0..2047、変数は最大4個（レジスタに割り当て）
- 関数定義は `void 名前(char *s) { ... }` の形（型は読み捨て、
  引数は1つまで、戻り値は無し）。引数は `a0` で渡し、戻り先は
  スタックに退避するので、関数が関数を呼ぶこともできる
- KosabaOS の print loop そのもの
  `void uart_puts(char *s) { while (*s != 0) { putc(*s); s = s + 1; } }`
  に呼び出し側を付けたプログラムがコンパイルでき、
  実行すると文字列が出る
- 目下の目標は、KosabaOS の print loop（`uart_puts`）を
  コンパイルできるように育てること（計画は `doc/roadmap.md`）
- `iwac` は、実行時にプログラムを計算して最後の式の値の下1バイトを
  UART に出し、止まる RISC-V (rv64i) の生バイナリを標準出力に
  書き出す（`65` だけなら16バイト、文や項が増えると少しずつ育つ）
- 出力バイナリは QEMU virt で `-kernel` に渡すと、OpenSBI が
  `0x80200000` に置いて実行する（KosabaOS と同じ土俵）

## ビルドと実行

ビルド（最初はホストの gcc で。将来のセルフホストは夢として置く）:

```sh
gcc -std=c11 -Wall -Wextra -O2 -o iwac iwac.c
```

コンパイルと実行:

```sh
./iwac examples/hello.c > hello.bin   # ファイルから読む (v10〜)
qemu-system-riscv64 -machine virt -bios default -kernel hello.bin \
    -m 128M -nographic  # シリアルに Hello, World! と出る

./iwac '65+1' > a.bin   # 従来の形 (引数そのものをコンパイル)
qemu-system-riscv64 -machine virt -bios default -kernel a.bin \
    -m 128M -nographic  # シリアルに B と出て止まる (終了は Ctrl-A x)
```

まとめて確認する検証スクリプトもある:

```sh
./test.sh
```

環境の作り方（ツールの種類・バージョン・入手方法）は
`doc/environment.md` にメモしてある。ツール本体はこのリポジトリには
入れず、手元ディスクの別ディレクトリに置く。

# v47 設計メモ: enum と union

位置づけ: doc/missing-features.md の実装予定 4
「enum / union / ビットフィールド」のうち、
enum と union を実装する (2026-11-19、ユーザーの
指示)。ビットフィールドは今回も対象外 (下の
「切り捨て」)。

## enum

### 形

    enum [タグ] { 名前 [= 定数式], ... } ;

- 定義はファイルの範囲だけ (typedef・構造体の
  定義と同じ作法)。関数の外でだけ書ける。
- タグは任意。タグがあれば `enum タグ` を型として
  使える。中身は int と同じ (型タグ 8、大きさ 8)。
  typedef もできる (`typedef enum Color Color;`
  の C の idiom も受ける)。
- 列挙子の値は定数式 (eval_const で種別 1 に
  なるもの)。省略したら前の値 + 1 (最初は 0)。
  前の列挙子を式の中で参照できる。
- 値は符号つき 32 ビットの範囲に限る。はみ出たら
  エラー (case ラベルの範囲点検と同じ物差し)。

### 実体

- タグ表 etag_* (32 個まで) と、列挙子の表
  econ_* (名前 → 値、256 個まで) を、構造体の
  タグ表 (stag_* / smem_*) と並べて 02-parse.c
  に置く。共有の宣言は src/decls.c にも足す。
- 式の中の列挙子は、parse_primary_node が
  変数・配列・関数のどれでもない識別子を引いて、
  数のノードに化かす。正の値は NODE_NUM、
  負の値は NODE_NEG (NODE_NUM) で、-1 の
  リテラルが解析される形と揃える (eval_const の
  NODE_NUM の扱いが符号なし 32 ビットなので、
  負の列挙子をそのまま NODE_NUM にすると
  case ラベルや初期化子で値が食い違うため)。
  だから生成 (gen) に変更は無い。
- 定数として効く場所は、eval_const が届く場所
  すべて: ファイル範囲の初期化子、配列の初期化子、
  case ラベル、列挙子自身の値の式。
- 配列の大きさにも使えるようにする: 大きさを
  読む場所 (宣言・メンバ・関数ポインタの配列) は
  数字の代わりに列挙子も受ける (parse_const_value)。
- 同じタグの再定義は、列挙子の並び (名前と値) が
  完全に同じなら受ける (構造体の再定義と同じ
  作法。分割コンパイルで共有ファイルが重なる
  ため)。列挙子単体も、同名・同値の再登録は
  受け、同名・別値はエラー。
- タグの名前空間は struct / union と共有として
  点検する: 構造体タグと同名の enum タグ (その
  逆も) はエラー。

### 割り切り (enum)

- 列挙子と同名の変数・引数は作れない
  (define_var_full で点検する)。iwac の代入文は
  暗黙に変数を作るので、点検しないと「列挙子への
  代入」が新しい変数として通ってしまうため。
  C では関数の中の同名ローカルは影として合法
  だが、iwac では一律にエラーにする。
- 逆向き (変数が先、列挙子が後) の定義側の
  衝突は点検しない。その場合、読む場所では
  変数が優先され、列挙子は見えなくなる。
  関数・配列と列挙子の衝突も同様 (関数・配列が
  優先)。
- 列挙子のスコープはファイル全体 (関数の
  中で定義できないので、C のブロック範囲の
  列挙は出てこない)。

## union

### 形

    union タグ { メンバ... } ;

- 定義・タグ・メンバの仕組みは構造体と共有する:
  stag_* / smem_* に載せ、stag_union の印だけ
  立てる。`struct` と `union` のキーワードの
  使い分けは parse_type で点検する (union の
  タグを struct で使う、その逆はエラー)。
- レイアウトだけが違う: 全メンバのオフセットが
  0 で、大きさは最大のメンバの大きさ (全体の
  アラインメントで切り上げ)。アラインメントは
  構造体と同じ (メンバの最大)。
- メンバ読み書き、丸ごと代入、値渡し・値返し、
  配列の要素、構造体メンバ・union メンバの
  入れ子は、構造体の既存の仕組みがそのまま
  効く (オフセットと大きさしか見ていないため)。
  生成 (gen) に変更は無い。
- 初期化子は先頭のメンバだけ: `union U u = { 値 };`
  2 つ目以降の値はエラーにする (構造体の初期化子
  parse_struct_init に union の分岐を足す)。
  書かれなかった分の 0 埋めは union ではしない
  (同じ場所を後から 0 で消してしまうため)。
  `{ }` (全 0) は従来どおり全メンバ 0 埋めで
  よい (全部 0 なので順序に依らない)。

## 切り捨て

- ビットフィールド (`int x : 3`) は今回も
  対象外。メンバの後ろの `:` はエラーになる。
- enum の値の式に浮動小数点は使えない
  (eval_const の種別 1 だけを受ける)。
- ファイル範囲の union / 構造体の初期化子は
  v45 の見送りのまま (nori の初期値モデルが
  1 変数 1 語のため)。

## 容量

- 新しい表: etag_* (タグ 32)、econ_* (列挙子
  256)、stag_union (32)。iwac で訳すと静的
  データは約 14KB 増える見込み。
- 断片プロファイル (kosaba/build-frag.sh) は
  econ_* を小さくする置換を足して 1MB 枠に
  収める (実測して決める)。
- 関数上限への影響: 新しい関数は find_enum_tag /
  find_enum_const / parse_enum_def /
  parse_const_value の 4 つ (実測 226 → 230、
  上限 256 に余りあり)。

# 可変長引数の設計 (v51 候補)

位置づけ: `...` で終わる関数 (printf 形式) を
書けるようにする設計メモ (2026-11-22、
ユーザーが設計メモ作成を承認)。実装はまだ
しない。動機は生態系の部品として: ユーザー
プログラムのデバッグ印字が putc や型ごとの
自作ヘルパーの手作業になっていて、nami も
デコーダも実機デバッグは印字頼みのため。

## 現行の呼び出し規約 (前提の確認)

- A 方式 (通常): 引数は最大 8 つ、a0〜a7 で
  渡す。ただし呼び出し側は、引数の式を右から
  評価して一旦スタックへ 16 バイト間隔で全部
  積んでから、a0〜a7 へ移す。受け側は a0〜a7
  を自分の枠へ写す
- B 方式 (v45、構造体が絡む呼び出し): 引数は
  全部スタックの引数領域に 16 バイト間隔で
  並び、受け側は fp 相対 (fp + スロット×16)
  で自分の枠へ写す。構造体の戻り値は先頭
  スロットの sret 経由

可変長が本物の C で面倒なのは、名前なし引数
がレジスタとスタックに散る規約のせい。
iwac には B 方式で「引数領域」の前例が既に
あるので、そこへ寄せる。

## 設計の芯: 可変長関数は引数領域で呼ぶ

- `...` を持つ関数の呼び出しは、構造体が
  絡まなくても B 方式と同じ「引数領域」
  規約で統一する: 名前つき・名前なしの全
  引数を 16 バイト間隔でスタックに積み、
  レジスタ渡しはしない
- 受け側は名前つき引数を B 方式と同じに
  fp 相対で枠へ写す。名前なし引数の先頭は
  fp + (名前つきのスロット数 × 16) で、
  ここが va_start の指す場所になる
- 戻り値は A 方式と同じ (スカラは a0)。
  構造体の戻り値 (sret) は対象外 (後述)

## 利用者から見える形

#include が無いので stdarg.h 方式は取らない。
syscall3 (v27) の前例に倣い、組み込みで出す:

- va_list は新しい型を作らず、ただの
  ポインタ (char * 等) として使う。利用者が
  自分で変数を宣言する
- va_start(ap, 最後の名前つき引数): 組み込み
  の特殊形として parse する。ap に「名前なし
  引数の先頭の住所」を入れる。コンパイラは
  引数領域の配置を知っているので、最後の
  名前つき引数の名前から次のスロットの
  オフセットが決まる
- va_arg(ap, 型): 第 2 引数は式でなく型。
  sizeof (v48) と同じく型名を読む特殊形に
  する。ap の指すスロットをその型で読み、
  ap を 1 スロット (16 バイト) 進める
- va_end(ap): 何もしない (置き場だけ用意)

## 呼び出し側の決まり

- 署名表に「可変長」印を 1 つ足す。宣言と
  定義で印が食い違えばエラー。関数ポインタ
  の署名 (fsig) にも印を含める
- 呼び出しの引数の数チェックは「名前つきの
  数以上」に緩める。名前つき分は従来どおり
  受け側の型へ変換する
- 名前なし分には C の既定の格上げ (default
  argument promotions) をかける: char /
  int16 系 (符号つき・なしとも) は int32 へ、
  double はそのまま、ポインタはそのまま、
  int32 / int64 はそのまま
- したがって va_arg で読める型は int32 /
  int64 / double / ポインタ型だけにする。
  char 等で読もうとしたら「格上げされて
  いるので int で読んでください」とエラー
  (本物の C でも va_arg に小さい型は書けない)

## 割り切り (v1 の範囲外)

- 可変長関数に構造体の引数・戻り値はなし
  (名前つき・名前なしとも)。B 方式の sret
  と引数領域の併用はしない
- va_copy はなし
- 型の間違い (書いた側と読む側の不一致) は
  本物の C でも未定義動作なので、検査なし

## 実装の置き場所 (見通し)

- parse: パラメータ並びの末尾で '.' が 3 つ
  続いたら可変長として読む (02b-decl.c の
  署名登録と、02-parse.c の引数チェック)。
  va_start / va_arg は新しいノード種か、
  専用の組み込み呼び出しとして表す
- gen: 可変長印のある呼び出しは gen_b_call
  系の積み方に寄せる (構造体なしの単純形)。
  受け側の序文は B 方式の写しを流用し、
  名前なし分の先頭住所を va_start の特殊形
  が fp 相対で作る
- iwac 自身のソースでは、できるまで `...`
  を使わない (従来どおり)

## 検証の形 (test.sh)

- printf もどき (書式 %d %s %x %c %%) を
  テスト側で書き、名前なし引数 0 個〜複数個、
  int / 文字列 / ポインタ / double (ビット
  パターンで照合) を混ぜて出力一致を見る
- 格上げの確認: char の 200 を渡して int で
  読むと 200 (iwac の char は符号なし。
  2026-11-22 に実測で確認済み)
- 名前つき引数が従来どおり届くこと、関数
  ポインタ経由の呼び出し、引数不足はエラー
  になること
- 既存の呼び出し (A/B 方式) の出力バイトが
  変わらないこと (回帰は digest で見る)

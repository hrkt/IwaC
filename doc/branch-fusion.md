# 条件分岐の融合の設計メモ (v53)

状態: 実装済み (2026-11-23、branch `v53`)。
最適化トラックの段2 (doc/optimization.md の
候補2)。段1 peephole (v52) の次。結果は末尾。

## 現在の生成形 (事実)

条件の位置 (if / while / do-while / for の
条件、三項演算子の条件) では、まず式を t1 の
0/1 に作ってから beq t1, zero で分岐する
(gen_cond_expr + emit_beq_t1z)。比較の
0/1 化は演算子で違う:

- `<` `>`: slt (sltu) 1 命令
- `<=` `>=`: slt + xori 1 で 2 命令
- `==`: sub + sltiu で 2 命令
- `!=`: sub + sltu で 2 命令

つまり条件1つにつき、両辺の評価の後に
2〜3 命令が付く。&& と || は短絡の分岐を
内部に持ちながら、最後に 0/1 へ正規化
(sltu や addi 1 + jal) してから外側の
beq で判定し直すので、条件の位置では
正規化が丸ごと無駄になる。

## 実測 (対象の静的カウント)

nami_all.c (mp3dec + nami、4,642 行):

- 条件の位置に比較を含むもの: 約 257 件
- 条件に && / || を含むもの: 約 29 件

融合すると比較1つで 1〜2 命令減る
(<= >= == != が 2、< > が 1)。静的には
nami 全体で 350〜450 命令 (約 2〜3%) の
見込みで、ループ条件に集中する分だけ
動的な効きは静的率より大きい。

## 仕組み

### 新しい分岐命令 (OP_BLT / BGE / BLTU / BGEU)

今の命令表にある条件分岐は beq と bne
だけ。新しく符号付き/なしの大小分岐を
4つ足す (OP は 58〜61、符号化は B 形式で
funct3 が 4/5/6/7)。触る場所は3か所:
04-encode.c の符号化と op_name、asari の
op_names と符号化、03-gen.c の命令定数。

### emit_branch への一般化と relax

emit_beq_t1z を emit_branch(op, rs1, rs2)
に広げる。短い形は分岐そのもの、長い形は
「反対の分岐で jal を飛び越える」形で、
反対の対応は beq↔bne、blt↔bge、
bltu↔bgeu。分岐の通し番号 (branch_ord) と
branch_long の仕組みはそのまま使う。

relax_scan は今「OP_BNE = 長い形の相方」
という暗黙の前提で数えている。一般化後は
走査側が branch_long[ord] を見て、その
通し番号が短い形か長い形かを知る形に
変える (長い形なら相方の jal も読み飛ばす)。
do-while のコメントにある「新しい分岐種を
relax に足さない」という割り切りは、この
一般化で正式に置き換える。

peephole との関係: 融合した分岐の asm_imm
も命令番号なので、v52 の索引の詰め直しが
そのまま効く。分岐命令自身は削除候補に
ならず、窓の境界扱いも従来どおり。

### gen_cond_branch (条件を分岐として生成)

条件の位置専用の再帰関数を新設する。
引数は「飛び先のパッチリスト」と「向き」
(真なら飛ぶ / 偽なら飛ぶ)。飛び先が複数に
なる (&& の偽向きは2本) ので、単一の命令
番号でなく patch_next のリストで受け、
呼び出し側は apply_patches で一括で
確定させる (break / continue と同じ道具。
条件のリストは文の生成の中で確定し切る
ので、ループの鎖と混ざらない)。

- 比較 (整数): 両辺の評価は gen_expr の
  二項演算と同じ段取り (左を t1、右は葉
  なら t2、式なら退避して t2) を共用し、
  最後に比較命令でなく分岐を置く。
  偽向きの対応 (真向きは反対の命令):
  - `<`: bge(u) t1, t2
  - `>`: bge(u) t2, t1 (両辺を入れ替え)
  - `<=`: blt(u) t2, t1
  - `>=`: blt(u) t1, t2
  - `==`: bne t1, t2 / `!=`: beq t1, t2
  符号なしはどちらかが uint64 のとき
  (今の ucmp と同じ判定)
- `&&`: 偽向きは両辺とも偽向きで同じ
  飛び先へ。真向きは左を偽向きで近くの
  合流点へ飛ばし、右を真向きで本命へ
- `||`: && の双対
- `!`: 向きを反転して再帰
- それ以外 (関数呼び出し、素の値、double
  が絡む比較や論理): 従来形に落とす。
  gen_cond_expr で 0/1 を作り、beq/bne
  t1, zero をリストに繋ぐ。意味は変わらず
  最適化だけ外れる

### 呼び出し側の変更

if / while / do-while / for (03-genstmt.c)
と三項演算子 (03-gen.c) の5か所を、
「gen_cond_expr + beq 1本」から
「リスト + gen_cond_branch (偽向き)」に
替える。do-while は今の形 (偽なら末尾へ
+ jal で戻る) を保つ。

## やらないもの

- double の条件の融合: feq / flt の結果を
  直接分岐に繋ぐ形は、値の置き場 (ft0) の
  規約と絡むので今回は落とし先の従来形で
  通す。件数も少ない
- switch の分岐: 値の振り分けであって
  条件の融合とは別物
- 分岐先の分岐の解消 (jump threading):
  optimization.md の候補7。分岐緩和の
  パスに相乗りする話で、段が違う

## 検証と効果測定

- test.sh に構造の検査を足す: 比較条件の
  小片で、slt / sltiu が出ず分岐命令が
  直接出ること、命令数の上限
- 機能の検査は既存の全シナリオ (出力の
  一致) が担保する。特に && || ! の
  組み合わせ、三項演算子、do-while の
  継続条件、範囲外分岐 (大きな関数での
  relax の長い形) を厚く見る
- 効果測定は v52 と同じ土俵: nami_all.c の
  命令数と、iwac 自身のソースでの命令数。
  セルフホストの固定点は形が変わるので
  digest が変わるのは前提 (正しさは実行
  テストで担保、という doc/optimization.md
  の約束どおり)

## 結果 (2026-11-23、branch `v53`)

設計どおりに実装した。test.sh 362 ok PASS
(v53 の検査2件を含む)。nami の命令数は
15,485 → 14,915 (−570、約3.7%減) で、見積もり
(2〜3%) をやや上回った。iwac 自身の一括では
insts 18,248 → 16,299、セルフホストの iwac2 は
295,088 バイト (Misoni でもバイト一致)。

実装で設計から動いた点と、途中で踏んだ点:

- 大小分岐の追加で、decls.c の OP が4つ増え、
  全断片のオブジェクトの変数が +4 になった。
  nori 断片プロファイルの edata 上限 (64、
  実測ピーク 63) を破ったので、上限を 80 へ
  緩めた (nori/build-frag.sh、実測ピーク 67)。
  nori-frag のデータは 398,515 バイト
- Asari の op 名前表が 58 枠固定で、新しい op が
  「知らない op」になった。表と lookup の範囲を
  64 に広げた (iwac 側の op_name は関数のため
  無事だった)
- test.sh の構造検査で、slt の件数を数える
  grep -c が 0 件で 1 を返し、set -e に殺されて
  スイートが無言で止まった。|| true を足した
- 意味の個別確認: 6種の比較、&& || ! の組み
  合わせ、三項、do-while、for、uint64 の符号
  なし比較 (bltu / bgeu)、4KB 超の本体での
  relax の長い形、すべて期待どおりの出力。
  `unsigned long` は従来どおり符号つき比較で、
  旧コンパイラと出力が一致することも確かめた
  (ucmp が効くのは uint64 の綴りのときだけ、
  という既存の仕様)

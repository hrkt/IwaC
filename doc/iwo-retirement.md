# .iwo 引退の設計 (v42)

## アーキテクチャ決定の記録 (2026-11-08)

**決定: オブジェクト形式は ELF を採用し、
.iwo は deprecated として現行コードベース
から無くす。** 仕様の記録 (doc/object-format.md)
は歴史的資産として残す。

判断材料にしたメリット・デメリット:

メリット:
- 保守が一本化される。新機能のたびに形式側の
  仕事が複数箇所に出る問題 (v40 で iwac の
  ainit 記録・ELF 節・Asari の素通しの3箇所)
  が消える
- 物差しが軽くなる。「両形式でバイト一致」の
  検証自体が不要になり、test.sh から参照
  リンカ mini_nori も消せる
- nori が小さくなる (テキスト解析の読み口が
  消え、断片プロファイルの 1MB 枠に余裕)
- 正本が一言で言える (「オブジェクトは
  ELF」)。readelf 等の世間の道具が全経路で
  使える

デメリット:
- 移行コストがまるごと1バージョン分。
  一番重いのは Asari への ELF 書き手の追加
- 目で読める形式 (1行1レコード) を失う。
  ELF は readelf 経由で、iwac 独自の意味は
  ELF の流儀に翻訳して読む形になる
- Asari の「薄い符号化器」という性格が少し
  濁る (ELF 書き手を抱えるため)。物差しは
  「Asari の .eo == iwac の .eo」で保つ
- 言語拡張 (switch 等) が後ろにずれる。
  ただし Ikesu 側のブロッカーではない

結論の要旨: 払うコストは今回の一回限りで、
得る軽さは恒常的。v39/v40 の知識が新しい
今が一番安い、という判断で実施する。

## 決定 (経緯)

2026-11-08、ユーザーが .iwo (自作テキスト
オブジェクト形式) の引退を決めた。仕様の記録
(doc/object-format.md) は歴史的資産として
残し、現役の形式は ELF オブジェクト (v39、
doc/elf-object.md) に一本化する。

.iwo は段1〜段6 の階段を支えた形式で、役割は
終わった: ELF 経由のリンクが .iwo 経由と
バイト一致することが v39 以来の物差しで
確認できており、残る利用者は移行できる。

## 現役の利用者 (引退で動くもの)

1. **Asari**: 出力が .iwo。チェーン
   (iwac → .ias → Asari → オブジェクト →
   nori) の要なので、ELF 書き手を Asari に
   足すのが一番大きい仕事
2. **nori**: .iwo と ELF の両読み。 .iwo の
   読み口 (テキスト解析) を撤去する
3. **iwac**: `--object` 出口 (write_object)
   を撤去する。再配置の収集 (obj_* の表) は
   --elf / --asari と共有なので残す
4. **Misoni**: マニフェストが --object を
   使っている。 --elf への切替が、そのまま
   残件だった「Misoni の標準経路の ELF 化」
   になる
5. **test.sh の mini_nori**: .iwo を読む
   参照リンカ。分割チェックは v39 以来の形
   (nori で ELF オブジェクトをリンクして
   一括版と比べる) に寄せて引退させる

## 手順 (各段で物差しを通してから次へ)

1. **Asari の ELF 出力**: asari.c に ELF
   書き手を足す (iwac の write_elf_object と
   同じ意味論。シンボルの数え直し方式も同じ)。
   物差し: Asari の .eo が iwac の .eo と
   バイト一致 (現行の .iwo 一致の置き換え)
2. **Misoni の ELF 切替**: マニフェストと
   駆動を --elf に。物差し: OS 上の固定点が
   従来どおり一致
3. **nori の .iwo 撤去**: テキスト読み口を
   抜く。.iwo を渡したら形式エラーにする
4. **iwac の --object 撤去**: write_object と
   obj_hex 系の .iwo 専用書き手を抜く
5. **test.sh の追随と全体 PASS**: mini_nori
   引退、.iwo 前提のチェックを ELF 前提へ
6. **文書**: doc/object-format.md の冒頭に
   「歴史的記録 (v42 で引退)」と明記して
   残置。elf-object.md / README / roadmap /
   selfhost / progress / phases.html を更新

## 触らないもの

- .ias (Asari への入力テキスト) は現役のまま。
  引退するのは .iwo だけ
- 一括コンパイルとベアメタル出力は不変
- doc/object-format.md は消さない

## 実装の記録 (v42、2026-11-08、branch `v42`)

手順どおりに実施した:

1. **Asari の ELF 出力**: asari.c の .iwo 書き手
   を、iwac の write_elf_object の移植に置換
   (レコードから関数・変数・配列の順位を数え
   直して組み立てる)。物差し「Asari の .eo ==
   iwac の .eo」は全コーパスで一致 (全断片・
   nori・Asari 自身・rt・構造体・配列初期化子・
   仮定義の合併)
2. **Misoni の ELF 切替**: misoni.sh と
   misoni.c の起動文字列を --elf に。ホストで
   iwac2 が一括と一致 (OS 上の固定点は
   test.sh の段6 で再確認)
3. **nori の .iwo 撤去**: テキスト解析と
   読み口を削除 (約300行)。ELF 以外は
   「ELF オブジェクトではありません」で止まる
4. **iwac の --object 撤去**: write_object を
   削除。--object はファイル名として扱われ
   開けない旨のエラーになる
5. **test.sh の追随**: mini_nori を削除。
   v31 の形の確認は readelf に、v32〜v40 の
   リンク確認は nori の ELF リンクに寄せ、
   v38 の物差しは .eo 同士の一致に、v39 の
   物差しは一括との一致に置き直した。v42 の
   節で「--object が通らない」「nori が .iwo
   を受けない」ことを固定
6. **プロファイルの追随**: 断片プロファイルの
   オブジェクト比較は --elf に。nori 断片の
   入力バッファは、ELF 化で最大オブジェクト
   (03-gen.eo、173,544 バイト) が育った分を
   180KB に増量し、データ 1,047,689 バイトで
   1MB 枠に収まる (余裕は約900バイトと薄い。
   次に nori の表を太らせる時は注意)

結果の数字: iwac の静的データ 3,745,269
バイト (v41 から微減)、digest は
len=197646 sum=0000000000be4113
hash=3979c2a40b92502b (write_object の削除で
iwac2 自体が小さくなった)。

# v60 設計メモ: int32 の W 形式化と正規化の削減

**状態: 実装済み (2026-11-24、branch `v60`)。
結果は末尾の「結果」節。**

## 背景

計測フェーズ (2026-11-24) で、生成コードの
太りの本体が「演算ごとの後始末」だと分かった。
tau ループ 1 周約48命令のうち実仕事は
5〜6 命令で、内訳は:

- int32 の正規化ペア (演算ごとの slli/srai)
  が約8命令
- 評価器の mv の往復が約12命令
- 帰納変数の更新 3 つが各5命令
- 基底アドレスの毎周の組み立てと退避

このメモは 1 番目 (正規化) を扱う。2026-11-21 の
Ikesu 連携で候補に挙がった「32bit 演算」の
具体化でもある。

## 現状の仕組み

値は 64 ビットレジスタに正規形 (符号つきは
符号拡張、符号なしは 0 拡張) で保つ決まり。
幅つき型 (etype の sized ビット) の演算結果は
emit_canon が slli + srai/srli のペアで正規形に
直す。ロードは lw/lwu が拡張まで済ませるので
無料だが、演算のたびに 2 命令払っている。

## 設計

### 置き換え

結果の etype が「符号つき・sized・32 ビット」
の二項/単項演算について、64 ビット演算 +
正規化ペア (3 命令) を W 形式 1 命令に替える。
W 形式は下位 32 ビットで計算し、結果を符号
拡張して返すので、正規形がそのまま得られる。

| 演算 | 現在 | W 形式 |
|---|---|---|
| + | add + ペア | addw (即値は addiw、既存) |
| - | sub + ペア | subw |
| * | mul + ペア | mulw |
| / % | div/rem + ペア | divw / remw |
| << >> | sll/sra + ペア | sllw / sraw (即値は slliw / sraiw) |
| 単項 - | sub + ペア | subw (0 から) |

### 正規化を省けるだけの箇所

ビット演算 (and/or/xor) は、正規形同士の
演算結果がそのまま正規形になる (符号ビット
同士の演算が符号拡張と一致する)。結果の
etype が符号つき sized 32 のときは W 形式は
無いが、emit_canon のペア自体を省ける。

### 対象外 (今回は触らない)

- 符号なし 32 ビット: W 形式は符号拡張して
  返すため正規形 (0 拡張) にならない。
  置き換えても命令数は減らないので現状維持
- 8/16 ビット: 対応する W 形式が無い
- 比較: 正規形同士の 64 ビット比較で正しい
- 型変換の境界 (int64 への拡張、キャスト、
  引数・戻り値): 正規化は今までどおり要る

### 意味の変わる隅

シフト量は W 形式では下位 5 ビットだけを
見る (mod 32)。現在は 64 ビットシフト後に
切り詰める形で、シフト量が 0..31 の範囲では
結果は一致する。範囲外は C でも未定義なので、
int32 のシフトとしては mod 32 の方が自然な
意味になる。ここは割り切りとして記録する。

割り算の隅 (0 除算、INT_MIN / -1) は div と
divw で同じ RISC-V の決まり (0 除算は -1、
溢れは割られる数自身) なので変わらない。

## 必要な追加

- エンコーダ (04-encode): W 形式の R 形式
  (opcode 0x3B) と即値形式 (0x1B、addiw は
  v27 で導入済み) の符号化
- Asari: 新しい mnemonic (addw ほか) の受理。
  nami は Asari 経由でビルドするので必須
- 二項演算の生成 (03-gen の gen_expr) と
  前置/後置の増減など、emit_canon を呼ぶ
  箇所の棚卸し: 「結果が符号つき sized 32
  なら W 形式にして canon を省く」を
  演算の種類ごとに決める

## 検証

- test.sh: 既存の int32 演算テスト一式 +
  境界の追加 (INT_MIN/INT_MAX の加減、
  シフト 0/31、mulw の溢れの切り捨て)
- セルフホストの固定点: iwac 自身が int
  演算だらけなので、iwac2 のバイト一致が
  強い回帰網になる
- PERFSTG で ST44 を測り直し (段ごと・合計)、
  nami の静的命令数も記録する

## 期待値 (正直な見積もり)

tau ループで 1 周 6〜8 命令の削減、行列
ループの添字でも同様。ST44 合計で
-8〜-15% の見込み。これ単独で実曲 1.4 倍の
溝は埋まらない。残りの太り (評価器の mv の
往復、基底アドレスの再組み立て) は別の
段として続ける。

## 結果 (2026-11-24)

実装は設計どおり: 新命令 9 個 (addw/subw/
mulw/divw/remw/sllw/sraw/slliw/sraiw) を
エンコーダと Asari に追加し、gen_expr の
二項演算 (レジスタ形・即値形)、単項マイナス、
++/-- (変数・要素) で、結果が符号つき
sized 32 のときに W 形式へ替えて正規化を
省いた。ビット演算の正規化省略は、レジスタ
形では両辺の etype が同じ形のときだけ、
即値形では結果の形だけで判定する (数
リテラルは 0 埋めで作られるため、レジスタ
形で片辺がリテラルだと結果が正規形に
ならない場合がある)。

副次効果: divw 化で INT_MIN / -1 の結果が
32 ビットで折り返すようになった (従来の
64 ビット div では正規形から外れていた)。

PERFSTG (ST44、同一イメージで v58 と交互
3 回、最小値): 合計 792M → 611M 命令
(-23%)、段5 は約 481M → 277M (-42%)。
デコードの FNV は不変。nami 静的命令数
17,885 → 16,753 (-6.3%)。見積もり
(-8〜-15%) を上回ったのは、添字式の
ように int32 演算が連なる箇所で、正規化
ペアの削減が複利で効いたためと見る。

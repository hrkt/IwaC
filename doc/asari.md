# Asari 呼び出しの設計: gen から Asari への受け渡し

Asari は iwac の第3層 (encode) を独立プログラムに
切り出したものの名前 (doc/linking.md「その先の
挑戦」)。この文書は、その切り口 — 生成層 (gen) が
Asari に何をどう渡すか — を仕様として書き切る。
2026-11-07 に設計だけを決めた (実装はまだ)。

(2026-11-08 追記: v42 で Asari の出力は .iwo
から ELF オブジェクトに替わった。受け渡し
(.ias) は不変で、全体像は
`iwac --.ias--> Asari --ELF--> nori --> ELF`、
物差しは「Asari の .eo が iwac の .eo と
バイト一致」。本文中の .iwo への言及は v38
設計時点のものとして読むこと。引退の記録は
doc/iwo-retirement.md)

これは ABI の文書である。コンパイラと Asari は
互いの中身を見ず、この受け渡しだけを信じて別々に
育つ。だから「何を固定し、何を固定しないか」が
設計の中心になる。

## 全体像

```
iwac (parse + gen) --.ias--> Asari --.iwo--> nori --> ELF
```

- iwac は新しい出口モード (仮に `--asari`) で、
  命令列とその付属情報をテキスト (.ias) に出す
- Asari は .ias を読み、符号化して、現行の
  オブジェクト形式 (.iwo、doc/object-format.md)
  を出す。nori は無変更でその後ろに付く
- 物差しはバイト一致: RISC-V では、Asari の出す
  .iwo が、iwac 内部の encode が出す .iwo と
  完全に一致すること (nori に対する mini-nori と
  同じ構図)

v1 の範囲はオブジェクト経路 (--kosaba --object)
だけにする。ベアメタルと KosabaOS ELF の直接出力
は内部 encode が残る (テストの大半が使う経路を
いきなりは動かさない)。

## 受け渡すもの

現行の encode (src/04-encode.c) が消費している
材料が、そのまま受け渡しの全体になる:

1. 命令列 (下記)
2. 呼び出しの注記 (call / callopt)
3. 住所作りの注記 (addrstr / addr / addabs)
4. 入口の情報 (prefix の長さ、flush の位置)
5. データ側の写し (strings / arrays / func /
   decl / var / varc / arr / init / iptr / undef)

5 は現行 .iwo の同名レコードと同じ意味で、
Asari は中身を解釈せず写すだけ (ただし func の
位置と大きさは「命令番号」から「バイト位置」への
換算が要る。下記)。住所作りの材料 (文字列の
中での位置など) も、現行 .iwo と同じ値を渡す。

## 命令列の形式

1命令1行、命令番号の順に並べる:

```
i <op名> <rd> <rs1> <rs2> <imm>
```

- op は名前で書く (lui、addi、beq、…)。番号は
  iwac 内部の事情なので持ち出さない。名前の
  一覧と意味は現行の OP_* (src/03-gen.c) が正本で、
  この文書の対訳表 (AArch64 の節) が全 op を
  網羅する
- レジスタは番号 (0〜31) で書く。今の iwac では
  この番号が RISC-V の番号と一致しているが、
  仕様としての意味は「役回り」である:

| 番号 | 役回り |
|---|---|
| 0 | zero (常に 0) |
| 1 | ra (戻り先) |
| 2 | sp (スタック) |
| 5 | t0 (ベアメタルでは UART の窓口専用) |
| 6 | t1 (今の値。式の評価の中心) |
| 7 | t2 (次の項。作業用) |
| 8 | fp (フレームポインタ) |
| 10〜16 | a0〜a6 (引数。a0 は戻り値も兼ねる) |
| 17 | a7 (システムコール番号) |

  翻訳する Asari は、この役回りを自分の arch の
  物理レジスタへ写してよい (例: AArch64 では
  a7 の役は x8、sp は本物の SP)。ただし Asari の
  出力同士と、同じ Asari で訳された rt との間で
  一貫していることが条件。入口で OS から受け取る
  値 (sp、argc/argv の置き場) はターゲットの
  約束 (OS の軸) が決める

- imm の意味は op の区分で決まる:

  - 分岐とジャンプ (beq / bne / jal で imm >= 0):
    飛び先の「命令番号」(バイト数ではない)。
    バイト距離への変換は Asari の仕事
  - 関数呼び出し (jal で相手が関数): 命令列の
    行では imm を 0 とし、行き先は call 注記で
    名前で渡す (内部の「負数で関数番号」という
    符号化は持ち出さない)。kosaba_flush への
    呼び出しは callopt 注記 (未定義なら消える
    呼び出し、という意味も注記が持つ)
  - 住所作りの組 (auipc + addi): オブジェクト
    経路では両方とも imm 0 で出し、対象は addr
    注記で渡す (現行のオブジェクト出力と同じ)
  - それ以外 (load / store / ALU / 定数作り):
    即値は最終値そのまま

## 注記レコード

位置はすべて「命令番号」で書く (現行 .iwo では
バイト位置だったところ):

```
call    <命令番号> <関数名>
callopt <命令番号> kosaba_flush
addrstr <命令番号> <文字列の中のオフセット>
addr    <命令番号> var <変数名> 0
addr    <命令番号> arr <配列名> 0
addabs  <命令番号> <絶対アドレス>
```

意味は現行 .iwo の同名レコードと同じ。Asari は
符号化のときに自分の対応表でバイト位置に直し、
.iwo 側の再配置レコードとして出す。

呼び出しの jal の符号化は「オフセット 0」を
正規形とする。リンカは呼び出し位置のオフセットの
桁を捨てて自分で書き直す (nori は下12ビットだけ
残す) ので、穴の桁に何が入っていても意味は
変わらない。そこで iwac 内部の encode も同じ形に
揃えた (v38 の変更。従来は内部の印 (負数) の値で
桁が埋まっていた)。

入口の情報:

```
prefix <命令数>     入口の断片の長さ (命令 [0, n) が
                    入口。入口を持たない断片では
                    Asari がこの範囲を落とす)
flush  <命令番号>   入口の kosaba_flush 呼び出しの
                    位置。無ければ -1
target kosaba       現行 .iwo が持つ対象の行と同じ
```

## Asari の仕事

1. 命令を符号化しながら「命令番号 → 出力での
   バイト位置」の対応表を作る
2. 飛び先 (命令番号) を対応表で引いて、その
   arch の相対オフセットに直す
3. 注記をバイト位置の再配置レコードに直す
4. データ側のレコードを写す (func の位置と
   大きさは対応表で換算する)

### 展開の原則 (固定しない部分)

1つの命令は、出力では「連続した何語か」になる
(0語にはならない)。飛び先は常に対象の命令番号の
先頭に着地する。言い換えると:

- 命令が何語に伸びるかは Asari の自由。分岐の
  届く範囲、命令の長さ、定数作りの方法の違いは
  全部この内側に閉じ込める
- 分岐緩和 (届かない条件分岐を長い形に伸ばす)
  は、今の iwac では gen の仕事のままにする
  (gen が生成と点検を繰り返して最終形の列を
  渡す)。Asari は渡された列をそのまま訳す。
  ただし arch 側の都合で伸ばす必要が出たら
  (届く範囲が RISC-V より狭い arch)、展開の
  原則の範囲で Asari が伸ばしてよい

## AArch64 の射程

狙いの1つ目は AArch64 (ラズパイ)。iwac の命令列
が RISC-V 形のままでも、翻訳型の Asari で吸収
できるかを、全 op の対訳で確かめる:

- そのまま1命令: add / sub / and / or / xor /
  mul / sll / sra / srl / slli / srai / srli
  (lsl / asr / lsr 系)、slt / sltu (cmp + cset)、
  addi / xori (add / eor の即値形)、
  ld / sd / lh / lhu / lw / lwu / sh / sw /
  lbu / sb (ldr / str 系。符号付きオフセットは
  unscaled 形がある)、jalr (br / blr)、
  wfi (そのままある)
- 固定の展開: beq / bne → cmp + b.eq / b.ne
  (2語。届く範囲は ±1MB で RISC-V の ±4KB より
  広いので、gen の緩和した列は必ず収まる)、
  jal → b / bl (±128MB)、div / divu →
  sdiv / udiv、rem / remu → 除算 + msub
  (余り専用の命令が無いので2〜3語)、
  addiw → 32ビット加算 + sxtw (符号拡張の
  向きが違うので1語では済まない)
- 組で訳す: auipc + addi (住所作り) →
  adrp + add。addr 注記が組の目印になる
- 注意が要る:
  - 定数作り (lui + addiw / addi の並び) は
    値が即値として列に焼かれているので、AArch64
    では movz / movk の並びへの「パターン読み」
    が要る。当面は gen の出す並び (生成の仕方は
    gen_load_const が正本) を読む形にし、将来
    要れば `const <命令番号> <値>` 注記を足して
    Asari が自分の並びを合成できるようにする
    余地を残す
  - ecall → svc。番号の置き場 (a7 の役 → x8) と
    呼び出し命令が OS の軸との接点。KosabaOS 用
    か Linux 用かは target の指定で Asari が
    選ぶ (番号そのものは列の中のデータ)
  - sp (役回り 2) は x2 ではなく本物の SP に
    写す。sp 相対の load / store と sp の増減は
    AArch64 にそのままの形がある

結論: AArch64 では、命令列の形式を変えずに
全部の op が訳せる。形式に AArch64 専用の
レコードは要らない。

## x86-64 の正直なところ

射程には「出来れば」で入れておくが、壁の場所は
書いておく:

- 吸収できる見込み: 2オペランドの破壊的な形は
  mov + 演算の展開で、除算のレジスタ固定
  (rdx:rax) は t1 / t2 の役回りが分かっている
  ので前後の退避で、どちらも展開の原則の内側
- Asari では直せない: 引数レジスタが6個まで
  しかない (iwac は8個まで使う)。呼び出しの
  並び自体が gen の生成なので、7・8個目を
  スタックに置く形に変えるなら gen 側の仕事に
  なる。形式は x86 を禁止しないが、対応は
  「gen の選択肢」が先で、v1 の射程には入れない

## 移植可能性の基準 (2026-11-08、ユーザーの方針)

x86 系への移植は、骨格が出来てからの話でよい
(今はやらない)。ただし後から「全然無理」と
ならないよう、今の設計で移植可能性を閉じない
ことを基準として明記する:

- 守る継ぎ目は Asari の境界。gen は符号化を
  知らず、命令列は抽象的な命令の名前と
  レジスタの役回りで Asari へ渡る (この文書の
  「固定するもの」がその契約)。ここが綺麗な
  限り、移植は「そのアーキテクチャ用の Asari
  を書く」仕事でいられる
- x86 の「2オペランドで破壊的」は、上の節の
  前提どおり Asari の内側でコピー挿入として
  吸収する。その前提を崩す変更をしない:
  gen 層や .ias 形式が RISC-V の命令の癖
  (3オペランドが当然にあること、即値の形、
  特定の符号化) に依存する形にしない
- gen 側の交渉点は、上の節に書いた引数
  レジスタの件 (7・8個目) が既知の唯一のもの。
  同種の前提を黙って増やさない。増やす必要が
  出たら、この文書に交渉点として書き足して
  からにする

## 実装の記録 (v38、2026-11-07)

上の段取りの 1〜3 まで実装済み:

- iwac に `--kosaba --asari` の出口を足した
  (src/04-encode.c の write_asari。材料は
  write_object と共有)。内部 encode は残してある
- Asari 本体は asari/asari.c (iwac の言語で書き、
  libdashi を使う。nori と同じ作り)。符号化は
  内部 encode_inst の移植で、計算は long で行い
  最後に32ビットに丸める
- test.sh に物差しを入れた: hello、全断片
  (decls.c + 各断片)、nori、Asari 自身、rt、
  構造体の断片で「--object と --asari → Asari が
  バイト一致」、加えて iwac → Asari → nori の
  チェーンが直接の ELF と一致すること
- KosabaOS 上 (virt) でもチェーンを通した:
  Nish から iwac.elf --asari → asari.elf →
  nori.elf → hello.elf で "Hello, World!"
- Misoni への差し込み (段取りの 4) はまだ。
  チェーンは手で回せるようになったので、
  マニフェストで回す形は必要になってから

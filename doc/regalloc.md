# レジスタ割り付けの設計メモ (v56 候補)

状態: 設計のみ (2026-11-23)。最適化トラックの
段4 (doc/optimization.md の候補4「ローカル
変数のレジスタ保持」)。段3 式評価 (v55) の次。
着手前にこの設計で合意を取りたい。

## いまの姿 (実測)

ローカル変数は全部フレームのスロットにあり、
読むたびに ld、書くたびに sd している。読み
書きの入口は gen_load_var / gen_store_var の
1対に集約されている (src/03-gen.c)。

nami (mp3dec 込み、14,285 命令) の内訳:

- ld / sd の総数 2,376
- うち fp 相対 (ローカル変数とローカル配列の
  交通) が 838

割り付けの対象はこのうちスカラのローカル
変数分。効きどころはループの中 (カウンタ、
蓄積変数、ポインタ変数) で、静的な命令数より
動的なメモリ往復の削減が本命。

## 設計

### 割り付け先

callee-saved の s レジスタ: s1 (x9) と
s2〜s11 (x18〜x27) の最大 11 本。生成コードは
いま s0 (fp) しか使っていない。callee-saved
なので、関数呼び出しを跨いで値が保たれる
(iwac 生成の関数は使えば序文で退避する。
gcc 製の rt も ABI どおり退避する)。

### 対象と除外

対象: その関数の中で完結するスカラの
ローカル変数と引数。

除外 (安全側の割り切り):

- 住所を取られる変数 (&var が関数内に1つ
  でもあれば、その変数は丸ごと対象外。
  ポインタ経由の読み書きと競合しないため)
- 配列・構造体のローカル (要素アクセスは
  住所計算の経路で別扱い)
- double のローカル (浮動小数点レジスタの
  割り付けは別の話として切る)
- グローバル変数 (別コンパイル単位や nori の
  配置と絡むので対象外)

### 選び方

関数ごとに本体の AST を歩き、変数ごとの
参照回数 (NODE_VAR の出現数) を数える。
多い順に最大 11 個まで割り付け、同数なら
変数番号の小さい方を先にする (決定的にする。
生成が2パス + relax で繰り返されても同じ
結果になること)。参照 4 回未満の変数は
割り付けない (退避・復帰と引数の写しで
相殺されるため)。

### 生成の変え方

- 割り付け表 var_reg[] を関数ごとに作る
  (純粋に AST から決まるので、フレーム長の
  計算 func_frame_size からも呼べる形にする)
- gen_load_var: 割り付けがあれば ld の代わりに
  mv (addi rd, sX, 0)。値はいつも正規形で
  レジスタに保たれるので、幅つき型でも
  そのまま移すだけ
- gen_store_var: 割り付けがあれば sd の代わりに
  mv。ただし幅つき型は、メモリに書くときの
  切り捨て (sb / sw) が無くなるので、移す前に
  正規化 (emit_canon 相当) を入れる
- フレーム: 退避する s レジスタの分だけ
  frame を広げ (func_frame_size に加算)、
  ra / fp の下 (fp-24 から下向き) に退避する。
  ローカルのずれは var_frame_off がフレーム長
  から計算するので自動で揃う
- 序文: fp を張ったあと、使う s レジスタを
  退避。引数は、割り付けがあれば a レジスタ
  (A方式) / 引数領域 (B方式) からスロットで
  なくレジスタへ写す
- 後始末: 戻り値の飛び先ラベルの先で s レジ
  スタを復帰してから従来の後始末へ (return は
  全部ここを通る)

### 触らないもの

- 引数の渡し方そのもの (呼び側は不変)
- t1 / t2 と保持レジスタ t3〜t6 (v55) の規約
- peephole (v52): s レジスタの move は対象の
  パターンに当たらないが、「レジスタ番号を
  見て判断する規則が s を壊さないこと」は
  実装時に確認する

## リスクと確認どころ

1. ecall (システムコール) を跨いで s レジスタ
   が保たれるか: KosabaOS のトラップ処理が
   レジスタを保存する前提。putc / write を
   挟む検査で確かめる
2. フレーム長の変化が B方式 (構造体引数・
   sret) のずれ計算と喧嘩しないか: 既存の
   v45 の検査が網になる
3. 再帰関数: 呼び出しごとに序文で退避する
   ので保たれる。fib の検査で確かめる
4. relax の再生成で割り付けがブレないか:
   割り付けは AST の純粋関数なのでブレない
   (セルフホストの固定点が最終確認)

## 見込み

nami の fp 相対 838 のうち、スカラ変数分が
大半と見て、静的に 200〜300 命令減 (約2%)。
本命は動的: 合成フィルタ等の内側ループで、
カウンタと蓄積変数の ld / sd が消える。

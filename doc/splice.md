# 行継続 (スプライス) の設計 (v41)

## 背景

Ikesu 独自デコーダ段6 で踏んだ癖の4番目:
代入文を行またぎで書き、次の行が `=` で始まる
形がパースエラーになる。原因は文の読み方で、
parse_body の文種別の先読みが空白とタブしか
飛ばさない (改行を跨いだ代入を見分けられない)。

標準 C には行継続の仕組みがある: 行末の
バックスラッシュは翻訳フェーズ2で改行ごと
消える (スプライス)。字句に割る前の処理なので、
文の途中でも識別子の途中でも効き、多行マクロも
これで成り立つ。iwac はこのフェーズを持って
いなかった。

## 方針: 入力層で一度だけ消す

置き場所は入力層 (src/05-input.c)。ソースが
src_buf に揃った時点で、バックスラッシュ+改行
の並びを全部消す。前処理 (expand_defines) より
前なので、指令行の継続も自然に効く。

- 対象は全入力: ファイル (load_file)、
  複数ファイル (load_files)、引数文字列。
  引数文字列はいま argv を直接指しているが、
  形を揃えるため src_buf へ移してから処理する
  (load_text を新設。上限は約384KBで
  ファイルと同じ)
- 消し方は1パスの前詰めコピー。対象は
  `\` + LF と `\` + CRLF
- 複数ファイルは連結後の全体に一度だけ
  かける。ファイル末尾のバックスラッシュは
  境目の改行を食べて次のファイルと繋がる
  (連結して1つの翻訳単位という iwac の
  模型と一貫させる)

## 意味の割り切り (C のフェーズ2どおり)

- 文字列・文字リテラルの中でも消える
  (フェーズ2は字句より前)。`"abc\` の次の行の
  `def"` は "abcdef" になる
- `//` コメントの行末にバックスラッシュが
  あると、コメントは次の行まで続く
  (C の有名な落とし穴だが、忠実な方を取る)
- バックスラッシュが2つ並んだら、消えるのは
  改行に接した2つ目だけ (左から1パスなので
  自然にそうなる)
- ソース末尾のバックスラッシュ (後ろに改行が
  無い) はそのまま残す

## 直らないもの

バックスラッシュ無しの行またぎ (文の途中の
ただの改行) は引き続きエラーになる。あれは
parse_body の先読みが改行を飛ばさない話で、
直すなら文の読み方の改修になる。今回の範囲は
「C の行継続を C どおりに効かせる」まで。

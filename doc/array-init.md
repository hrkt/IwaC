# 配列初期化子の設計 (v40)

ファイルスコープの配列に初期化子を書けるように
する: `int32 a[3] = { 1, 2, 3 };` と
`char s[6] = "hello";`。動機は Ikesu の独自
MP3 デコーダ (段6 で判明した不足): 表が約
26,500 定数あり、実行時代入への展開は命令表
(49,152) を超えるので、値はデータとして
運ばなければならない。

現状 (2026-11-08): 配列宣言は `;` で終わる形
しか受け付けず、`=` 自体がエラーになる。
スカラーの初期化子 (v24) は「一括では入口の
代入コード、オブジェクトでは init 記録」と
いう二本立てだが、配列は個数が桁違いなので
両経路ともデータで運ぶ (コードにはしない)。

## 文法 (v1 の範囲)

- 対象はファイルスコープの配列だけ。関数の中の
  配列初期化はエラー (「関数の中の配列初期化は
  まだできません」)
- 要素はスカラー数値型 (char / int / long /
  幅つき整数) とそのポインタでない配列。
  構造体の配列とポインタの配列はエラー
- 形は2つ:
  - `{ 値, 値, ... }`: 値は定数だけ (符号つき
    数値リテラル、文字リテラル)。2次元では
    行ごとの `{ ... }` を入れ子にしてもよい
    (平らに読む)。末尾のカンマ可
  - 文字列リテラル (char 配列のみ): C の意味
    どおり、収まれば末尾 0 を付け、ちょうど
    なら付けない。収まらなければエラー
- 要素数が宣言の大きさより少ない分は 0 で
  埋まる (C の意味どおり)。多いのはエラー
- 大きさの省略: `int a[] = { ... };` は要素数
  から大きさを決める。2次元は1次元目だけ
  省略可 (`int a[][3] = { ... };`)。
  初期化子なしの省略は従来どおりエラー

## 値の運び方

parse が値を貯める: 配列ごとに「何要素分
書かれたか」(arr_init_cnt) と、値の置き場
(長い配列1本のプール、arr_init_pool[65536]、
8バイト/要素。対価は静的データ約 0.5MB、
標準版の余裕の内側)。gen は何もしない
(アドレスも領域も従来どおり)。

- 一括 (write_binary): データイメージの配列
  領域に、書かれた範囲のバイトを要素の大きさ
  で切り詰めて置く。ファイル長 (filesz) は
  最後に初期値のある配列の末尾まで伸びる
- オブジェクト (.iwo): `arr` 記録の直後に
  `ainit <名前> <バイト数>` + 16進の行を足す。
  nori は配置した配列の場所へそのバイトを
  写し、最終 ELF の filesz を同じ規則で伸ばす
- オブジェクト (ELF): 初期値のある配列が
  1つでもあれば `.iwac.arrays` を PROGBITS
  にして領域全体のイメージを持つ (なければ
  従来どおり NOBITS)。nori は中身のある節を
  初期イメージとして写す
- Asari: write_asari が同じ ainit 記録を出し、
  Asari 本体は素通しで .iwo に写す

## 割り切りと残件

- 要素の式は定数リテラルだけ (名前や演算は
  まだ)。`&` や文字列ポインタの要素もまだ
- ローカル配列の初期化 (実行時コードが要る)
  はしない。必要になったら別途
- mini_nori (test.sh 内の参照リンカ) は ainit
  を知らない。iwac 自身のソースは新機能を
  使わないので分割チェックには現れない

## 実装の記録 (v40、2026-11-08、branch `v40`)

設計どおりに実装した。要点と実測:

- parse は要素を式ノードにせず、専用の定数
  読み (parse_init_const) で値プールへ直接
  貯める。26,269 要素・315KB のソース
  (デコーダ級) が 0.5 秒でコンパイルできた
- 形の統一: 実体が届く末尾は「最後の 0 で
  ないバイトまで」で、一括版 (arr_init_end) と
  nori の両読み口 (.iwo / ELF) で同じ規則に
  した。これで一括 = .iwo 経由 = ELF 経由 =
  Asari 経由の最終 ELF がバイト一致する
- 分割 TU の仮宣言 + 初期値つき定義の合併も
  両形式・両リンク順で一致を確認
- 容量: 値プール 65,536 要素で静的データは
  3,745,572 バイト (4MB 領域の内側)。
  一括セルフコンパイルの命令数は 46,023
  (上限 49,152)。断片プロファイルはプールを
  4,096 / 1,024 要素に縮め、iwac 835,432
  バイト・shirasu 359,016 バイト。nori の
  断片版は ainit 置き場 4KB + edata 受け口の
  縮小 (1024 → 256、実測ピーク 57) +
  コード置き場の実測合わせで 1,028,109
  バイトに収めた

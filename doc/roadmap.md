# IwaC 計画案

確定仕様ではなく、進めながら見直す前提の計画案。
各ステップに「見える成果」を1つ置く方針（KosabaOSと同じ）。

## ゴール像

- KosabaOS 上のシェルから `iwac` を実行して Hello World を
  コンパイルし、実行できること（KosabaOS 側ゴールの一部）
- いつかはセルフホスト: iwac で iwac 自身をコンパイルできること
  （当面の必須条件ではなく、将来の夢として置く）

## 範囲（欲張らない）

- 対象外: プリプロセッサ（`#include` / `#define` など）、
  float、構造体、最適化
- Hello World は `#include <stdio.h>` に頼らず、使う関数を
  ファイルの中で自分で宣言する形で書けるようにする想定

## ステップ

### v0: 一番小さいバイナリ（済み、2026-11-01）

- 入力: 1文字、または 10進数 0..255
- 出力: その1バイトを UART に出して `wfi` で止まる
  RISC-V (rv64i) 生バイナリ、16バイト・命令4つ
- 実行: QEMU virt、ベアメタル（`-kernel` で `0x80200000` 配置）
- 見える成果: シリアルに指定した文字が出る
- 詳細と検証結果は `doc/progress.md`

### この先の候補（順番は未定、進めながら決める）

- UART 送信のポーリング（送信可能を待ってから書く。
  QEMU では無くても動くが、実機では本来いる処理）
- 式: `65+1` のような計算をして結果のバイトを出す
- 複数バイト: 文字列などを続けて出す
- Cらしい形へ: 文、変数、`return`、`if` / `while`、
  関数定義・呼び出し、ポインタ・配列、`char` と文字列リテラル
- アセンブリ経由や ELF 出力など、出力形式の見直し
  （v0 は生バイナリ直出し。KosabaOS 側に ELF ローダができたら再検討）
- KosabaOS 上で動かす: OS 側の進み具合（ユーザーモード、
  ファイル、シェル）と合流する

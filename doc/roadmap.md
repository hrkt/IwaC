# IwaC 計画

確定仕様ではなく、進めながら見直す前提の計画。
進め方の約束:

- **一歩一歩、順番に進める**。前のステップの検証が済んでから次へ
- 各ステップに「見える成果」を1つ置く（KosabaOSと同じ方針）
- 計画・設計・進捗はドキュメントに残して育てる
  （設計は `doc/design.md`、できたことは `doc/progress.md`）
- ソースには解説コメントを厚く書く。読んで学ぶのが目的

## ゴール像

- KosabaOS 上のシェルから `iwac` を実行して Hello World を
  コンパイルし、実行できること（KosabaOS 側ゴールの一部）
- いつかはセルフホスト: iwac で iwac 自身をコンパイルできること
  （当面の必須条件ではなく、将来の夢として置く）

## 範囲（欲張らない）

- 対象外: フルプリプロセッサ（`#include` など）、
  float、構造体、最適化
  - 例外の将来候補: 行内の特定文字列を置き換える程度の
    単純な `#define` は「そのうちやりたいもの」として
    下の将来ステップに置く（今はやらない）
- Hello World は `#include <stdio.h>` に頼らず、使う関数を
  ファイルの中で自分で宣言する形で書けるようにする想定

## ステップ

### v0: 一番小さいバイナリ（済み、2026-11-01）

- 入力: 1文字、または 10進数 0..255
- 出力: その1バイトを UART に出して `wfi` で止まる
  RISC-V (rv64i) 生バイナリ、16バイト・命令4つ
- 実行: QEMU virt、ベアメタル（`-kernel` で `0x80200000` 配置）
- 見える成果: シリアルに指定した文字が出る
- 詳細と検証結果は `doc/progress.md`

### v1: 式（足し算・引き算）（済み、2026-11-01）

- 入力: 数字と `+` / `-` だけの式。例: `65+1`
- やったこと:
  - 字句解析の最小形: 数字の並びと演算子に切り分ける
  - 左から順に計算する命令列を出す。計算はコンパイラが
    代行するのではなく、**実行時に** `add` / `sub` で行う
  - レジスタの約束は設計書の通り（`t1` = 今の値、`t2` = 次の項）
  - 解析（parse）と生成（codegen）を分離: 全部読み終わって
    から生成するので、文法エラーではバイナリを出さない
  - 項の上限は 2047（`addi` の即値が符号付き12ビットのため）
- 見える成果: `65+1` を実行すると `B`、`66-1` なら `A` が出る
- バイナリは項1つごとに少し育つ（`65+1` で 24 バイト）
- 詳細と検証結果は `doc/progress.md`

### 構造整理: 内部を3層に分離（済み、2026-11-01、v1の直後）

- 言語仕様は変えず、内部を3層に分けた（ユーザーの希望）:
  parse（ソース→AST）／ gen（AST→命令列。機械語の一歩手前）／
  encode（命令列→機械語ビット列→出力）
- AST は構造体・ポインタを使わず、並行配列＋ノード番号で表す
- 検証の要点は「出力バイナリが整理前と完全一致すること」

## 目標: KosabaOS の print loop をコンパイルする

（2026-11-01、ユーザーが次の目標に指定。式の `*` `/` かっこ
より優先する。print loop には要らないため後回しにした）

対象は KosabaOS の `uart.c` にある、この関数:

```c
void uart_puts(const char *s)
{
    while (*s != '\0') {
        uart_putc(*s);
        s++;
    }
}
```

この短い関数にも、iwac にはまだ無いものが詰まっている:
文字列とその置き場所、ポインタと `*s`（メモリ読み）、
変数と代入、`while` と分岐・ジャンプ、関数と呼び出し。
全部入りを一度にやらず、小ステップに割る:

### v2: 変数と代入、文の並び（済み、2026-11-01）

- プログラムが「代入文の並び＋最後の式」になった
  例: `x = 65; x + 1` → `B`
- 変数はレジスタに割り当てる（最大4個、`t3`〜`t6`）。
  代入されていない変数を使うとエラー（初回代入の右辺で
  自分自身を使うのもエラー）。再代入もできる
- v1 のプログラムは全部そのまま動く（出力も不変を確認）
- print loop への意味: `s` のような「持ち回る値」の土台

### v3: ポインタと文字列（済み、2026-11-01）

- 文字列リテラルをバイナリの後ろ（コードの後）に置き
  （末尾 0 付き）、変数にその住所を持たせられるようにした
- `*s` で1バイト読む（`lbu`）、`s = s + 1` で進める
- 文字列の住所は2パス生成で確定（1回目で命令数を数える）
- 住所の材料は auipc（PC 相対）にした: 当初試した
  lui + addi は、0x8020xxxx の住所が lui の符号拡張で
  壊れて load fault になったため（progress に記録）
- 見える成果: `s = "Hi"; *s` で `H`、`s = s + 1` して `i`

### v4: while と出力文で、print loop の本体（済み、2026-11-01）

- 組み込みの出力文 `putc(式);`（UART へ1バイト。当面は
  ポーリング無しの直接書き込みで、uart_putc の本体は v5 以降）
- `while (式) { ... }`（条件は「0 でない間」）と、分岐・
  ジャンプ: 命令列では飛び先を命令番号で持ち（beq は
  飛び先を後から書き直して確定）、encode で相対オフセット
  （B 形式 / J 形式）に変換する。文も AST ノードになった
- 達成形（iwac 言語形）:
  `s = "hello\n"; while (*s) { putc(*s); s = s + 1; }`
  を実行すると `hello` と出ることを QEMU で確認

### v5: C らしい形へ（関数・引数・呼び出し）（済み、2026-11-01）

- 関数定義（型は読み捨て、引数1つまで、void）と呼び出し。
  呼び出し規約: 引数は a0、戻り先 ra は関数の入口で
  スタックへ退避（コンパイラがバイナリの後ろに用意）。
  関数が関数を呼ぶ入れ子も動く
- 比較 `==` / `!=`（sub + sltu / sltiu で 1 か 0 を作る）
- 達成形: 本物の `void uart_puts(char *s) { while (*s != 0)
  { putc(*s); s = s + 1; } }` ＋呼び出し側がコンパイルでき、
  `hello` が出ることを QEMU で確認。**print loop 目標は
  ここまでで達成**（残るは uart_putc 本体側の丁寧さ）

### v6: uart_putc の本体（済み、2026-11-01）

- 入れた部品: 絶対アドレス読み `*0x10000005`（住所の材料は
  auipc 相対）、ビット演算 `&`、メモリ書き込み文
  `*住所 = 式;`、16進数リテラル。空の本体の while は
  既存の仕組みでそのまま書けた
- 優先順位の決め事: かっこがまだ無いので、`&` は比較より
  固く結ぶことにした（C とは逆）。これでポーリングの形
  `*0x10000005 & 32 == 0` がかっこ無しで書ける
- 達成形: 本物の `void uart_putc(char c) { while
  (*0x10000005 & 32 == 0) { } *0x10000000 = c; }` ＋
  uart_puts がコンパイルでき、`hello` が出ることを
  QEMU で確認。組み込み putc は互換のため残置

### v7: 演算子の優先順位を C に合わせる（済み、2026-11-01）

- ユーザーの指摘で実施: 優先順位は重要なので、C 準拠を
  先に済ませる。段を C の順に組み替えた（固い順に:
  ポインタ読みとかっこ、`*` `/`、`+` `-`、`==` `!=`、`&`）。
  かっこと乗除もここで入れた
- v6 で逆にしていた `&` と比較の順は C に戻り、
  ポーリングは `((*0x10000005 & 32) == 0)` と C と同じ
  かっこ付きの形で書く
- 評価の一般化: 右の子が葉でない式は、左の結果を
  スタックに退避して評価する（AST を歩いて必要性を
  先に判定し、要るプログラムだけ sp を用意するので、
  従来のプログラムの出力は不変）

### 後回しリスト（print loop には不要なもの）

- `if` などの他の制御構造、配列
- プログラム形を `main` を持つ形へ移すこと
- 入力をコマンドライン引数からファイルへ

### 将来: 単純な #define（時期未定、やりたくなったときの一歩）

- やること: `#define 名前 置き換え文字列` の形だけで、
  行内に出てくる名前を文字列として置き換える小さな前処理
  （例: `#define MAX 256` と書けば、以降の `MAX` が `256` になる）
- やらないこと: `#include`、引数付きマクロ、条件分岐
  (`#ifdef` など)。フルプリプロセッサにはしない
- 効きどころ: 定数に名前が付くとプログラムが読みやすくなる
  （項数の上限 256、UART のアドレスなど、繰り返し出てくる数）
- 実装するときに決めること: 置き換えは単語単位か部分文字列か、
  再定義や入れ子（define の中で define 名を使う）の扱い
- 入れる時期の目安: 入力がファイルになってプログラム自体が
  育ってきた頃。iwac が対応した後は、iwac 自身の
  ソースでも使ってよいことになり、test.sh の
  「プリプロセッサ行ゼロ」ガードもそのときに見直す

### 合流地点: KosabaOS 上で動かす

- OS 側の進み具合（ユーザーモード、ファイル、シェル、
  ELF ローダ等）と合わせて、出力形式と実行方法を再設計する
- 最終形: KosabaOS のシェルから `iwac hello.c` で
  Hello World をコンパイルし、実行できること

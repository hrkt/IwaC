# IwaC 計画

確定仕様ではなく、進めながら見直す前提の計画。
進め方の約束:

- **一歩一歩、順番に進める**。前のステップの検証が済んでから次へ
- 各ステップに「見える成果」を1つ置く（KosabaOSと同じ方針）
- 計画・設計・進捗はドキュメントに残して育てる
  （設計は `doc/design.md`、できたことは `doc/progress.md`）
- ソースには解説コメントを厚く書く。読んで学ぶのが目的

## ゴール像

- KosabaOS 上のシェルから `iwac` を実行して Hello World を
  コンパイルし、実行できること（KosabaOS 側ゴールの一部）
- いつかはセルフホスト: iwac で iwac 自身をコンパイルできること
  （当面の必須条件ではなく、将来の夢として置く）

## 範囲（欲張らない）

- 対象外: フルプリプロセッサ（`#include` など）、
  float、構造体、最適化
  - 例外の将来候補: 行内の特定文字列を置き換える程度の
    単純な `#define` は「そのうちやりたいもの」として
    下の将来ステップに置く（今はやらない）
- Hello World は `#include <stdio.h>` に頼らず、使う関数を
  ファイルの中で自分で宣言する形で書けるようにする想定

## ステップ

### v0: 一番小さいバイナリ（済み、2026-11-01）

- 入力: 1文字、または 10進数 0..255
- 出力: その1バイトを UART に出して `wfi` で止まる
  RISC-V (rv64i) 生バイナリ、16バイト・命令4つ
- 実行: QEMU virt、ベアメタル（`-kernel` で `0x80200000` 配置）
- 見える成果: シリアルに指定した文字が出る
- 詳細と検証結果は `doc/progress.md`

### v1: 式（足し算・引き算）（済み、2026-11-01）

- 入力: 数字と `+` / `-` だけの式。例: `65+1`
- やったこと:
  - 字句解析の最小形: 数字の並びと演算子に切り分ける
  - 左から順に計算する命令列を出す。計算はコンパイラが
    代行するのではなく、**実行時に** `add` / `sub` で行う
  - レジスタの約束は設計書の通り（`t1` = 今の値、`t2` = 次の項）
  - 解析（parse）と生成（codegen）を分離: 全部読み終わって
    から生成するので、文法エラーではバイナリを出さない
  - 項の上限は 2047（`addi` の即値が符号付き12ビットのため）
- 見える成果: `65+1` を実行すると `B`、`66-1` なら `A` が出る
- バイナリは項1つごとに少し育つ（`65+1` で 24 バイト）
- 詳細と検証結果は `doc/progress.md`

### 構造整理: 内部を3層に分離（済み、2026-11-01、v1の直後）

- 言語仕様は変えず、内部を3層に分けた（ユーザーの希望）:
  parse（ソース→AST）／ gen（AST→命令列。機械語の一歩手前）／
  encode（命令列→機械語ビット列→出力）
- AST は構造体・ポインタを使わず、並行配列＋ノード番号で表す
- 検証の要点は「出力バイナリが整理前と完全一致すること」

## 目標: KosabaOS の print loop をコンパイルする

（2026-11-01、ユーザーが次の目標に指定。式の `*` `/` かっこ
より優先する。print loop には要らないため後回しにした）

対象は KosabaOS の `uart.c` にある、この関数:

```c
void uart_puts(const char *s)
{
    while (*s != '\0') {
        uart_putc(*s);
        s++;
    }
}
```

この短い関数にも、iwac にはまだ無いものが詰まっている:
文字列とその置き場所、ポインタと `*s`（メモリ読み）、
変数と代入、`while` と分岐・ジャンプ、関数と呼び出し。
全部入りを一度にやらず、小ステップに割る:

### v2: 変数と代入、文の並び（済み、2026-11-01）

- プログラムが「代入文の並び＋最後の式」になった
  例: `x = 65; x + 1` → `B`
- 変数はレジスタに割り当てる（最大4個、`t3`〜`t6`）。
  代入されていない変数を使うとエラー（初回代入の右辺で
  自分自身を使うのもエラー）。再代入もできる
- v1 のプログラムは全部そのまま動く（出力も不変を確認）
- print loop への意味: `s` のような「持ち回る値」の土台

### v3: ポインタと文字列（済み、2026-11-01）

- 文字列リテラルをバイナリの後ろ（コードの後）に置き
  （末尾 0 付き）、変数にその住所を持たせられるようにした
- `*s` で1バイト読む（`lbu`）、`s = s + 1` で進める
- 文字列の住所は2パス生成で確定（1回目で命令数を数える）
- 住所の材料は auipc（PC 相対）にした: 当初試した
  lui + addi は、0x8020xxxx の住所が lui の符号拡張で
  壊れて load fault になったため（progress に記録）
- 見える成果: `s = "Hi"; *s` で `H`、`s = s + 1` して `i`

### v4: while と出力文で、print loop の本体（済み、2026-11-01）

- 組み込みの出力文 `putc(式);`（UART へ1バイト。当面は
  ポーリング無しの直接書き込みで、uart_putc の本体は v5 以降）
- `while (式) { ... }`（条件は「0 でない間」）と、分岐・
  ジャンプ: 命令列では飛び先を命令番号で持ち（beq は
  飛び先を後から書き直して確定）、encode で相対オフセット
  （B 形式 / J 形式）に変換する。文も AST ノードになった
- 達成形（iwac 言語形）:
  `s = "hello\n"; while (*s) { putc(*s); s = s + 1; }`
  を実行すると `hello` と出ることを QEMU で確認

### v5: C らしい形へ（関数・引数・呼び出し）（済み、2026-11-01）

- 関数定義（型は読み捨て、引数1つまで、void）と呼び出し。
  呼び出し規約: 引数は a0、戻り先 ra は関数の入口で
  スタックへ退避（コンパイラがバイナリの後ろに用意）。
  関数が関数を呼ぶ入れ子も動く
- 比較 `==` / `!=`（sub + sltu / sltiu で 1 か 0 を作る）
- 達成形: 本物の `void uart_puts(char *s) { while (*s != 0)
  { putc(*s); s = s + 1; } }` ＋呼び出し側がコンパイルでき、
  `hello` が出ることを QEMU で確認。**print loop 目標は
  ここまでで達成**（残るは uart_putc 本体側の丁寧さ）

### v6: uart_putc の本体（済み、2026-11-01）

- 入れた部品: 絶対アドレス読み `*0x10000005`（住所の材料は
  auipc 相対）、ビット演算 `&`、メモリ書き込み文
  `*住所 = 式;`、16進数リテラル。空の本体の while は
  既存の仕組みでそのまま書けた
- 優先順位の決め事: かっこがまだ無いので、`&` は比較より
  固く結ぶことにした（C とは逆）。これでポーリングの形
  `*0x10000005 & 32 == 0` がかっこ無しで書ける
- 達成形: 本物の `void uart_putc(char c) { while
  (*0x10000005 & 32 == 0) { } *0x10000000 = c; }` ＋
  uart_puts がコンパイルでき、`hello` が出ることを
  QEMU で確認。組み込み putc は互換のため残置

### v7: 演算子の優先順位を C に合わせる（済み、2026-11-01）

- ユーザーの指摘で実施: 優先順位は重要なので、C 準拠を
  先に済ませる。段を C の順に組み替えた（固い順に:
  ポインタ読みとかっこ、`*` `/`、`+` `-`、`==` `!=`、`&`）。
  かっこと乗除もここで入れた
- v6 で逆にしていた `&` と比較の順は C に戻り、
  ポーリングは `((*0x10000005 & 32) == 0)` と C と同じ
  かっこ付きの形で書く
- 評価の一般化: 右の子が葉でない式は、左の結果を
  スタックに退避して評価する（AST を歩いて必要性を
  先に判定し、要るプログラムだけ sp を用意するので、
  従来のプログラムの出力は不変）

### v8: if / else（済み、2026-11-01）

- `if (式) { 文の並び }` と `else`（中身は `{ }` の塊か
  文1つ。`else if` の連なりは文1つの応用として動く）。
  本体は while と同じく `{ }` 必須の形に揃えた
- 生成は while と同じ道具立て（beq で else へ、本体の
  末尾に jal で else を飛び越える。飛び先は後から書き直し）

### v9: 配列（済み、2026-11-01）

- 宣言 `char buf[16];`（要素は1バイト、型の単語は読み捨て）。
  置き場所はメモリの静的な領域（コード＋文字列の後ろ）で、
  住所は2パス生成で確定。スタックの天井は配列の分も
  避けて決めるようになった
- 要素の読み `buf[i]`・書き `buf[i] = 式;`（添字は式）。
  配列の名前そのものの値は先頭アドレスで、関数へ渡す・
  ポインタ変数に入れることができる。名前は変数と重ねない
- 配列は最大8個・合計4096バイト、プログラム全体で共有の
  1つだけ（局所配列やスコープはまだ無い）

### v10: ファイル入力（済み、2026-11-01）

- `iwac hello.c > hello.bin` の形で、ファイルを読み込んで
  コンパイルできるようにした。引数が `.c` で終わる名前
  なら必ずファイルとして開き（開けなければ専用の
  エラー）、それ以外でも同名ファイルが開ければその中身を、
  無ければ引数そのものをプログラムとして読む
  （従来の使い方も後方互換として残る）。上限は約64KB
- ファイルのために、空白として改行を飛ばせるようにし、
  行コメント `//`（行末まで、C と同じ決め事）を入れた。
  除算 `100/4` が壊れないことも確認済み
- ホストに頼る外部関数は write に open/read/close が
  加わって4つに。ここが KosabaOS 上で動かすときに
  システムコールへ差し替える場所になる
- 見える成果: リポジトリ同梱の `examples/hello.c`
  （コメント・改行入り、本物の uart_putc/uart_puts 入り）を
  コンパイルして QEMU で `Hello, World!` が出る

### v11: 関係演算子（済み、2026-11-01）

- `<` `>` `<=` `>=` を入れた。優先順位の段は C の順に
  add と eq の間へ差し込み（parse_rel_expr）、結果は
  「成り立てば 1、だめなら 0」
- 機械語は slt（符号付き比較）が中心。`>` は両辺を
  入れ替えた `<`、`<=` `>=` は反対の比較＋ xori 1 の反転
- 見える成果: `while (i < 3)` のような自然なループ

### v12: main の形（済み、2026-11-01）

- 名前が `main` の関数を入口として扱う。生成は
  「入口で main を jal で呼び、戻ったら wfi」の形で、
  main 自体は通常の関数と同じ作り（戻り先の退避込み）。
  main に引数は書けない
- main があるプログラムでは、外側の文・最後の式との
  混ぜ書きを禁止（C の作法）。main が無ければ従来の
  形のまま、出力も不変。`int` の戻り値は読み捨てで、
  終了コードの仕組みはまだ無い
- `examples/hello.c` も main の形に移行

### 後回しリスト（print loop には不要なもの）

- 残りの制御・データ構造（構造体など）

### v13: 単純な #define（済み、2026-11-01）

- 下記の計画どおりの範囲で実装した。置き換えは単語
  （識別子）単位で、文字列の中と `//` コメントの中は
  置き換えない。効きどころの実例: uart_putc が
  `#define UART_LSR 0x10000005` / `#define THRE 32` と
  名前で書ける
- 実装時に決めた点: 置き換えた結果は再走査しない
  （入れ子は展開しない）、再定義はエラー、define は
  最大16個・置き換えは127文字まで、`#define` は行頭
  （空白の後ろも可）だけ
- iwac 自身のソースは今もプリプロセッサ無しのまま
  （test.sh のガードも現状維持。これは「コンパイル
  される側」のための機能、という整理）

### 将来: 単純な #define（済み → v13。計画時のメモ）

- やること: `#define 名前 置き換え文字列` の形だけで、
  行内に出てくる名前を文字列として置き換える小さな前処理
  （例: `#define MAX 256` と書けば、以降の `MAX` が `256` になる）
- やらないこと: `#include`、引数付きマクロ、条件分岐
  (`#ifdef` など)。フルプリプロセッサにはしない
- 効きどころ: 定数に名前が付くとプログラムが読みやすくなる
  （項数の上限 256、UART のアドレスなど、繰り返し出てくる数）
- 実装するときに決めること: 置き換えは単語単位か部分文字列か、
  再定義や入れ子（define の中で define 名を使う）の扱い
- 入れる時期の目安: 入力がファイルになってプログラム自体が
  育ってきた頃。iwac が対応した後は、iwac 自身の
  ソースでも使ってよいことになり、test.sh の
  「プリプロセッサ行ゼロ」ガードもそのときに見直す

### 合流地点: KosabaOS 上で動かす

- OS 側の進み具合（ユーザーモード、ファイル、シェル、
  ELF ローダ等）と合わせて、出力形式と実行方法を再設計する
- 最終形: KosabaOS のシェルから `iwac hello.c` で
  Hello World をコンパイルし、実行できること

### v14: KosabaOS ターゲット出力（済み、2026-11-02）

- `iwac --kosaba ファイル.c` で、KosabaOS のユーザー
  プログラム用 ELF を出す。OS 側の仕様（syscalls.md v1、
  elf.c のローダ、vm.h の配置）に合わせた:
  - ELF64 / ET_EXEC / RISC-V、PT_LOAD 1本、入口と配置は
    0x40000000、p_filesz はコード＋文字列、p_memsz の
    差分（配列の領域）はローダがゼロ埋め
  - 組み込み putc と最後の式の出力は putc システム
    コール（a7=1）、終わりは exit システムコール（a7=3）
  - スタックは OS が用意するので自前の用意は出さない。
    UART の lui も出さない。住所の材料は auipc 相対の
    まま、基準 LOAD_BASE を 0x40000000 に差し替える
  - 従来（ベアメタル）ターゲットの出力は完全不変
- 統合検証（OS の作業ツリーのスクラッチコピーで実施、
  OS リポジトリ自体は無変更）: examples/hello-kosaba.c の
  ELF を uprog.elf として埋め込み、'u' 起動とシェルの
  `run uprog.elf` の両方で Hello, World! → 正常復帰を
  確認。**合流の第一歩が成立**
- 次: v15 = iwac 本体を OS のユーザープログラムとして
  ビルドする（4つの外注関数を OS の open/read/close/
  write 相当の syscall へ。write はファイル書き込みが
  要る点が要相談: 現行 syscall に write は無い）
  → その後 OS 側で create(9)/write(10) が実装され解消

### v15: iwac 本体の OS 移植（済み、2026-11-02）

- iwac.c は無変更。`kosaba/` に3点を追加してリンクを
  差し替える形にした:
  - kosaba_crt.S: 入口 _start。OS に argv の仕組みが
    無いので argv = { "iwac", "--kosaba", "hello.c" } を
    合成して main を呼び、終了時に exit syscall
  - kosaba_lib.c: write/open/read/close を syscall で
    再実装。fd=1 → create/write で hello.elf へ
    (バッファ付き)、fd=2 → putc のコンソール
  - kosaba.ld / build-kosaba.sh: 配置とビルド手順
- 統合検証でゴールの形が成立: OS のシェルで
  `run iwac.elf` → hello.elf が生成 → `run hello.elf`
  → Hello, World! → シェルへ復帰
- 当初は OS のコード領域が読み+実行のみで静的変数を
  持つプログラムが動けない問題があったが、OS 側が
  (b) 案（データ専用領域 0x40200000＋ローダの振り分け、
  KosabaOS 9416180）を実装。iwac 側は kosaba.ld を
  新配置に合わせ、OS 本線（無改造）での統合検証で
  ゴールの成立を確認済み
- 将来: OS に argv の仕組みができたら crt の合成を
  本物の引数に替える（替える場所は crt だけ）

## セルフホストへの階段（v16〜、2026-11-02 に計画）

目標: **iwac が iwac.c 自身をコンパイルできる**こと。
iwac.c の実測（2760行・約116KB）から、足りないものを
洗い出した。構造体・switch・三項演算子・sizeof・% は
iwac.c が使っていないので不要（% はついでに入れる）。
各段の設計メモと実装時に決める点は **doc/selfhost.md** に
まとめた。使う順に一段ずつ:

- v16 字句の完成（済み、2026-11-02）: ブロックコメント
  （`/*` 〜 `*/`、skip_spaces で読み飛ばし、閉じ忘れは
  lex_failed の印で失敗させる）、文字リテラル
  （'a' '\n' '\0' '\\' '\'' '\"'、値は文字コード）、
  型の語彙に long / unsigned / signed / short を追加
  （unsigned long のような並びも受ける。型は従来どおり
  読み捨てる）。型判定が parse_type・文の振り分け・
  配列宣言の3か所に重複していたので is_type_word に統一
- v17 複数ファイル入力（済み、2026-11-02）: `iwac a.c b.c` のように複数の
  ファイルを並べたら、順につないで1つのソースとして
  読む（ファイルの境目には改行を挟む）。ライブラリ側の
  ファイル＋本体、という分け方ができるようになり、
  v26 のランタイム結合（kosaba_rt.c + iwac.c）も
  cat の代わりに iwac 自身の機能でまかなえる。
  引数が1つだけのときの従来の規則（.c はファイル必須、
  それ以外は開ければファイル・無ければ引数そのもの）は
  そのまま残す
- v18 条件付きコンパイル（済み、2026-11-02）: 前処理に
  #ifdef / #ifndef / #else / #endif（入れ子32段まで）。
  無効な範囲の #define は登録されない。定義済みマクロ
  __IWAC__（常に）と __KOSABA__（--kosaba のとき）を
  用意し、ターゲットでソースを切り替えられる。#if
  （式の評価）は対象外のまま
- v19 演算子の完成（済み、2026-11-03）: `<<` `>>`、`|` `^`、
  `%`、`!`、`&&` `||`（短絡評価）、単項マイナス、
  前置/後置 `++` `--`。優先順位の段を C の全順序に揃えた
  （|| → && → | → ^ → & → ==/!= → 関係 → シフト →
  加減 → 乗除・剰余 → 単項 → 後置 → 材料）。`>>` は
  算術シフト（sra）。`&&` `||` は条件分岐で右を飛ばす
  短絡評価で、結果は 1 か 0。`++` `--` の相手は変数だけ

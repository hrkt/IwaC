# 式評価の改善の設計メモ (v54 候補)

状態: 設計のみ (2026-11-23)。最適化トラックの
段3 (doc/optimization.md の候補3)。段2 分岐の
融合 (v53) の次。

## 現在の生成形 (事実)

- gen_expr の約束は「結果は t1」。二項演算は
  gen_binop_operands が左辺を t1 に作り、右辺が
  葉なら t2 へ、葉でなければ左の結果をスタックへ
  退避して右を計算する。退避は addi sp,-16 /
  sd / (右の計算) / addi t2,t1,0 / ld /
  addi sp,+16 の 6 命令 (実質の無駄は 5)
- t3〜t6 (x28〜x31) は生成のどこでも使われて
  いない (事実確認済み)
- 定数相手の演算も li で t2 に入れてから演算
  する。即値形の OP は ADDI / SLTIU / XORI /
  SLLI / SRLI / SRAI / ADDIW が既にある
- 実測 (nami、14,915 命令): 二項演算の退避は
  150 か所 (約 750 命令)。定数を t2 に入れて
  レジスタ演算する形は 395 か所

## やること A: 退避をレジスタで受ける

gen_binop_operands の退避先を、まずレジスタで
受ける形にする:

- 保持レジスタの組は t3, t4, t5, t6 の4本。
  gen 中の大域カウンタ hold_depth で積み重ねる
  (入れ子の二項演算が内側ほど後のレジスタを
  使う)。4段を超えたら従来のスタック退避へ
- 形: addi t3, t1, 0 / (右を t1 に計算) /
  addi t2, t1, 0 / addi t1, t3, 0 の 3 命令
  (move が1つ増えるがメモリ往復と sp 調整の
  4命令が消える。差し引き1か所 2 命令減)
- **呼び出しを跨ぐときはレジスタに置かない**。
  t3〜t6 は呼び出しで壊れる (caller-saved)
  ので、右辺の部分木に呼び出し (NODE_CALL /
  NODE_ICALL) が含まれる場合は従来のスタック
  退避を使う。判定は部分木を lhs / rhs / next
  でたどる小さな再帰で、数え落とし側でなく
  余分に拾う側に倒す (迷ったらスタック)
- 引数を積む退避 (gen_call_args 等) は呼び出し
  規約そのものなので触らない。対象は二項演算の
  両辺評価だけ (gen_cond_branch も同じ道具を
  使うので条件側も自動で効く)

## やること B: 定数相手の即値形

右辺が定数の葉のとき、t2 に入れず即値命令で
直接演算する。差し込む場所は gen_expr の二項
演算の入口 (両辺評価の前) で、対象を絞る:

- + / - / & / | / ^ : addi / andi / ori / xori
  (定数が −2048〜2047 に収まるとき。− は
  符号を反転して addi。−2048 の反転は範囲外
  なので、その値だけ従来形)
- << / >> (論理・算術): slli / srli / srai
  (シフト量 0〜63)
- < (符号つき・なし): slti / sltiu (値の位置の
  比較だけ。条件の位置は v53 の分岐が担当)
- * : 定数が 2 の冪なら slli、0 なら 0 を置く、
  1 なら演算なし (左辺の評価と正規化は従来
  どおり行う)
- 新しい OP は ANDI / ORI / SLTI の3つ (62〜64)。
  v53 の教訓どおり波及を先に数える: Asari の
  op 名前表は 64 枠 → 72 枠へ、decls.c の
  変数 +3 で nori 断片の edata ピークは
  67 → 70 (上限 80 の内側)
- **ポインタ演算は対象外**: p + 5 の 5 は要素
  サイズでスケールされる経路 (v49) を通るので、
  迂回しない。どちらかがポインタ型なら従来形
- == / != の定数相手、/ % の定数相手は従来形
  (即値形が無い・既存の材料化に手を入れない)

## 割り切り

- 評価順の入れ替え (Sethi-Ullman) はしない。
  副作用の順序を変える risk に対して、保持
  レジスタ4段で浅い式は足りる。深い式は
  スタック退避が残るだけ
- 浮動小数点の式 (03b-genfp) は触らない
- 左辺が定数で右辺が葉、の交換 (5 + x) は
  しない (件数が少なく、形も別)

## 効果の見込み (nami)

- A: 150 か所 × 2 命令 ≒ −300 命令。退避が
  メモリ往復でなくなる動的な効きは別にある
  (内側ループの式に多い)
- B: 395 か所のうち即値に収まるものが大半で
  ≒ −250〜350 命令
- 合わせて静的 −4% 前後

## 検証

- test.sh に構造の検査を足す: 入れ子の式で
  スタック退避 (sd/ld の組) が出ないこと、
  定数相手で即値命令が出ること、命令数の上限
- 機能は既存の全シナリオの出力一致が担保。
  特に: 呼び出しを含む右辺 (跨ぎの判定)、
  4段を超える入れ子、ポインタ演算の不変、
  シフト量と負の定数の境界
- 効果測定は従来どおり nami の命令数と
  セルフホストの固定点

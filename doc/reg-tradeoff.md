# レジスタートレードオフの設計メモ (v59、実装済み)

v57 (ループ最適化) の残件。割り付け (v56) が
s レジスタ 11 本を使い切った関数では、歩く
ポインタの置き場が無く、変換が丸ごと入らない。
割り付けの末尾を外してポインタに明け渡す
トレードオフを入れる。対象の筆頭は nami の
synth_granule (デコードの約 6 割)。

## 実測 (nami、v58 の iwac で計測)

割り付け 11 本満杯で、候補のあるループが
全部落ちている関数は 5 つ、ループは 15 個:

- synth_granule: 8 ループ (np は下記)
- decode_huffman: 3 ループ (np=1 ずつ)
- build_fast: 2 ループ (np=1, 2)
- requant: 1 ループ (np=1)
- stereo_process: 1 ループ (np=1)

np = そのループが要るポインタの数。ポインタの
席は兄弟ループで使い回せるので、要るのは
「同時に生きる最大数」だけ。

synth_granule のループと np:

- 寄せ集め (sb[i] 書き): np=1
- cpv / cmv を作る (k<16): np=3
- dpv / dqv を作る (k<8): np=3
- 行列の内側 (k<8) ×3: np=1 ずつ
  (dpv / dqv / cmv の読み)
- 窓かけの tau ループ ×2: np=2 ずつ
  (synth_d[di] と synth_row[di])

synth_granule の割り付け (参照回数の多い順):
k=38, a=19, acc=16, d=14, ch=12, row=9,
voff=7, soff=7, v=7, t=6, i=6。

## 素朴な「末尾を外す」の落とし穴

参照回数だけで末尾を選ぶと、synth_granule
では i (6 回) と t (6 回) が外れる。だが:

- i は寄せ集めループ自身の帰納変数。外すと
  ループの条件と更新が毎周メモリ経由になり、
  ポインタで稼ぐ分 (1 周あたり約 1 命令) を
  食い潰しかねない
- soff (7 回) はソース側で既に手で歩かせて
  いるポインタそのもの (soff = soff - 64)。
  tau ループの中で読み書きされるので、外すと
  tau 側の得と相殺する

つまり「帰納変数」と「ループの中で自分が
歩いている変数」は外してはいけない。幸い、
v57 の計画が記録する変更箇所の表 (xform_mod)
に帰納変数は全部載っている。soff も
soff = soff - 64 が定数歩幅の変更として
記録されるので、同じ表で弾ける。

## 設計

計画は func_reg_plan の中で 3 段にする
(現行は割り付け → ループ計画の 2 段):

1. 割り付け (v56、現行どおり)
2. 見回り: ループ計画の走査だけを行い
   (loop_plan_one は呼ぶが、ポインタ表へは
   入れない)、(a) 変更箇所の記録を残し、
   (b) 予算で落ちたループの不足分
   = np + 祖先ループの np の合計 - 空き席、
   の最大値を数える
3. 明け渡しと本計画: 不足があれば、外せる
   変数を不足分だけ (上限 2 個まで) 外し、
   割り付け直してからループ計画を本実行する

外せる変数の条件と順序:

- 割り付け済みで、見回りの間に記録された
  変更箇所の表に載っていない (帰納変数でない)
- 順序は参照回数の少ない順、同数なら
  割り付け順の後ろ (席番号の大きい方) から

外した後は、残った割り付けの席番号を
詰め直す (順序は保つ)。序文・終文は
saved_reg_no(0..退避本数-1) を連続で退避する
決まりなので、穴が空いたままではいけない。
ポインタの席は詰め直した割り付けの後ろから
始まる (loop_plan へ渡す assigned が減る)。

synth_granule では、外せるのは voff と v
(どちらも 7 回、帰納変数でない) の 2 つが
先頭に来る。2 席空けると np<=2 の 6 ループ
(寄せ集め・行列 ×3・tau ×2) が入り、
np=3 の 2 ループ (cpv/cmv・dpv/dqv 作り、
周回 16 / 8 と短い) は残る。効き目の中心は
tau (1 グラニュルあたり約 18,000 周、2 本)
と行列の内側 (約 9,000 周、1 本) で、
静的な概算ではグラニュルあたり数万命令の
削減、デコード全体では数 % の見込み。
割り切りとして正直に書くと、これ単体で
実曲 128k の不足 (約 1.4 倍) は埋まらない。
物差しは virt の perf と実機 (従来どおり)。

上限を 2 個にする理由: synth_granule の
価値の大半は 2 席で取れること、外す変数が
増えるほど損の見積もりが読みにくくなる
こと。他の関数 (decode_huffman 等) は
不足 1〜2 で収まる。

## 決まりごとの確認

- 判断は関数の中だけで完結する (本体と
  自分の変数だけを見る) ので、一括 / 分割、
  標準 / 断片で判断が一致する (v58 で守った
  性質を崩さない)
- 計画は AST の純粋関数のまま。生成の
  2 パスと relax で結果はブレない
- 新しい表は要らない (見回りは不足分の
  最大値だけ数える)。断片データへの
  影響なし

## テスト

- test.sh に v59 のチェックを足す: 割り付け
  11 本満杯 + 候補ループのある関数で、歩く
  ポインタが入ること (Asari リスティングで
  添字の slli が消える形を確認)、帰納変数が
  外れないこと、機能の出力が不変なこと
- 既存の全チェックが通ること (特に v56 /
  v57 の構造チェックと、一括 / 分割一致)
- nami の静的命令数の変化を記録する

## 範囲外

- 上限 2 個を超える明け渡し、np=3 ループの
  部分的な採用
- 変換対象の形の拡張 (メンバ配列、
  row * 32 + k、定数 - 帰納変数) は別件
- 参照回数を動的に重み付けする精緻な
  コストモデル (見回りの不足分と帰納変数
  排除で v1 は足りると判断)

## 実装の結果 (2026-11-24、v59)

設計どおり実装した (src/03-gen.c の
func_reg_plan と loop_plan_visit)。

- nami で受け入れられるループは 8 → 20。
  落ちていた 15 のうち 12 が入った
  (decode_huffman の 3、build_fast の 2、
  requant、stereo_process も)
- synth_granule: 外れたのは v と voff
  (どちらも参照 7 回、帰納変数でない)。
  入ったのは寄せ集め (np=1)、行列の内側 ×3
  (np=1)、m ループ (np=2) の 5 つ。
  tau のポインタ (synth_d[di] と
  synth_row[di]) は、内側の tau ループでは
  なく m ループの席で取れた — di は m の
  中でリセットされないので、外側で張る方が
  初期化が少なくて済む。内側の tau ループ
  自身の計画は重複として落ちるが、その
  アクセスは m のポインタで覆われる
- 残るは np=3 の作り置きループ ×2
  (cpv/cmv・dpv/dqv)。上限 2 個の割り切り
  どおりで、周回も短い (16 / 8)
- 静的命令数 17,883 → 17,899 (+16、
  ほぼ不変)。効き目は動的な方で、
  物差しは virt の perf と実機

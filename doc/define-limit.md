# v50: #define の上限を 16 から 64 へ

## 動機

プリプロセッサ (v13) の #define は最大 16 個まで。
mp3 デコーダ (Ikesu 側、ハフマン多ビット表の作業) が
この壁に当たり、定数を直書きして回避した (2026-11-20、
ユーザーが緩和を希望)。実プログラムが当たる上限は、
当たった時点で緩めるのがこのプロジェクトの進め方。

## 変更

- 上限 16 → 64。対象は個数だけ。名前 31 文字まで、
  置き換え 127 文字までは据え置き (当たったのは
  個数の方だけ)。
- 実体は src/06-preproc.c の表 4 つ:
  def_names[66][32]、def_name_len[66]、
  def_text[66][128]、def_text_len[66]。
  ガード (ndef - ndef_base >= 64) とエラー文言
  「#define は64個までです」も一緒に替える。
  decls.c の宣言も寸法を合わせる。
- 表が 64 でなく 66 なのは、定義済みマクロ
  (__IWAC__ と、--kosaba 時の __KOSABA__) の
  2 枠を別に確保するため。定義済みマクロは
  ndef_base として上限の数え方から外し、
  利用者が書けるのはターゲットによらず
  ちょうど 64 個にする (実装中にテストで
  発覚: 素朴に表 64 では利用者分が 62〜63 個に
  なってしまう)。
- 静的データは +8,400 バイト (50 件 × 168 バイト)。
  標準ビルドは 2,873,164 → 2,881,564 バイトで
  問題なし。

## 断片プロファイルの扱い

iwac 自身のソースは #define を使わない (プリプロ
セッサ無しがソースの規律)。だから断片側は表を
16 のままに絞る書き換えを足し、1MB の枠を守る:

- kosaba/build-frag.sh: 06-preproc.c に表 4 つと
  ガード・文言の書き換えを追加 (66 → 18、
  利用者分は 64 → 16)。
  iwac-frag のデータは定義済み 2 枠の分だけ
  増えて 1,044,688 バイト (1MB 枠内)。
- kosaba/build-shirasu.sh: 同じ書き換えを追加。
  shirasu のデータも +336 バイトで 380,496。

つまり「標準の iwac で訳すプログラム」は 64 個まで、
「実機で動く小さい iwac (断片・shirasu) で訳す
プログラム」は従来どおり 16 個まで。実機側の iwac が
訳すのは iwac 自身か小さいプログラムで、どちらも
16 個で足りる、という割り切り。

## テスト (test.sh に v50 節)

- #define を 40 個定義して使うプログラムが
  正しく動く (check_tail)。
- 65 個目で「#define は64個までです」のエラーに
  なる (check_error)。
- 固定点は形が変わる (iwac 自身のデータが増える
  ため iwac2 のバイト列が変わる)。digest は
  実測して doc/selfhost.md に記録する。

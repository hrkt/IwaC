# ループ最適化の設計メモ (v57 候補)

状態: 設計のみ (2026-11-23)。最適化トラックの
段5 (doc/optimization.md の候補5「ループまわり」)。
段4 レジスタ割り付け (v56) の次。着手前にこの
設計で合意を取りたい。

## 狙い

ループの中で、添字アクセスのたびに組み直している
アドレス計算を減らす。現状の生成形では
`a[i]` の1アクセスで:

- 添字の拡大: slli (要素サイズが 2/4/8 のとき)
- 基底との加算: add
- 基底そのもの: グローバル配列なら auipc + addi
  の組、ローカル配列なら addi (fp 相対)

が毎回出る。nami (mp3dec 込み、v56 後) の
命令内訳では slli が 1,347、addi が 6,490
(総計 14,939)。このうちループ内のアドレス
計算がどれだけかは実装の初手で切り分けるが、
デコーダの内側ループ (合成の積和) は添字
アクセスの塊なので、ここが段5 の主戦場。

## 設計: 添字の強化削減 (strength reduction)

ループ変数そのものを添字にするアクセスを、
歩くポインタに置き換える。

- 対象のアクセス: `a[i]`、`a[i + 定数]`,
  `p[i]`、`p[i + 定数]` (i は帰納変数)。
  読みも書きも
- ループ入口で歩くポインタを1つ作る:
  ptr = 基底 + i の初期値 × 要素サイズ
- 本体の中のアクセスは ptr + 定数 × 要素サイズ
  (addi 1つ、または歩幅に畳み込める場合は
  そのまま) で置き換える。slli と add が消える
- 帰納変数の更新箇所 (代入・++ / --) で、
  ポインタも歩幅 × 要素サイズだけ進める

帰納変数の検出条件 (全部を満たすときだけ
適用し、1つでも外れたら従来の生成に落とす):

- ループは while / for / do-while のいずれか
- 帰納変数はスカラのローカル変数で、ループ内
  では定数歩幅の代入 (i = i + k、i += k) と
  ++ / -- だけで変わる。住所を取られていない
- 添字に使われる形は上記の4形だけ。その他の
  式に i が現れるのは構わない (i 自体は残す)
- break / continue / return があってもよい
  (ポインタはループの外では使わない)

歩くポインタの置き場: v56 のレジスタ割り付けと
同じ枠組みで、ループ専用の隠し変数を1つ足し、
s レジスタの空きに割り付ける。空きが無い
関数では適用しない (割り切り)。

## 副次: 不変基底の巻き上げ

グローバル配列の基底 (auipc + addi の組) は
強化削減のポインタ初期化に吸収される (入口で
1回だけ組む)。ローカル配列の基底も同じ。
それ以外のループ不変な式の巻き上げ (一般の
LICM) は今回の対象外とする。

## 割り切りと対象外

- 入れ子のループ: 内側のループにだけ適用
  する (外側の帰納変数を内側で使う添字は
  従来形)。検出が素直な方を取る
- 添字がループ変数でないアクセス (a[j] 等) は
  対象外
- 2次元配列・構造体メンバの添字は対象外
  (基底が式になるため)。1次元の配列と
  ポインタだけ
- 歩幅が実行時に決まる代入 (i = i + k で
  k が定数でない) は帰納変数とみなさない

## リスクと検証

- ポインタの進め忘れが最大のリスク: 帰納変数の
  更新は代入文の形 (NODE_ASSIGN) と ++ / --
  の両方に現れる。v56 の参照数えと同じく、
  更新箇所の列挙を AST の歩行で漏らさないこと
- continue は更新を飛ばす形 (for) と飛ばさない
  形 (while) でポインタの進み方が変わらない
  こと — 更新箇所にポインタの歩進を結び付ける
  ので、文の実行順がそのまま正しさを決める
- 検証: test.sh に構造検査 (対象ループで slli が
  消えること) と機能検査 (歩幅 1/2/負、途中の
  break / continue、書き込み、ポインタ版) を
  足す。nami では命令数と slli の減りを測る

## 見込み

内側ループの添字アクセス1つあたり 2〜3 命令
(slli + add、グローバル基底なら +2) が
1 命令以下になる。デコーダの合成は1タップに
複数アクセスがあるので、段5 (合成) の
命令数で 1〜2 割減を狙う。静的な総計より
動的な削減が本命なのは v56 と同じ。

# 基本機能の欠落と実装予定 (メモ)

位置づけ: iwac を C コンパイラとして見たときの
基本機能の欠落を整理し、実装予定として置くメモ
(2026-11-08、ユーザーと整理)。着手は一歩ずつ、
順番に。最適化 (doc/optimization.md) はこの
基本拡張が済んでから、という順番が方針。

## 実装予定 (困っている順)

1. **switch**: 基本制御構文で欠けている代表。
   Ikesu 側の不足リストの筆頭で、nami でも
   「無いので if-else で書く」となった (2026-11-08)。
   デコーダやインタプリタの振り分けで頻出する。
   次の言語拡張の第一候補
2. **関数ポインタ (間接呼び出し)**: 呼び出しは
   関数名の指名だけ。jalr は return 専用で、
   関数ポインタの typedef も明示的に「なし」。
   コールバックや関数テーブル (比較関数、
   ハンドラ表) が書けない
3. **構造体の値セマンティクス**: v37 の切り捨ての
   まま。値渡し・戻り値・丸ごと代入・初期化子が
   全部エラー。構造体は「置いてメンバを触る」
   だけで、値として受け渡せない
4. **enum / union / ビットフィールド**: enum は
   int 定数で代用できるが頻出。union はビット
   表現の読み替えで実コードによく出る
5. **小物**: do-while、sizeof (式) (今は型だけ)、
   goto、3 次元以上の配列、ローカル配列の
   初期化子、可変長引数

## 注意点: static と const は「読み捨て」

修飾子は文法上受けるが意味を持たない。関数内
static が普通の局所変数として扱われるなど、
エラーにならず意味だけ違う。欠落より厄介な
場合があるので、実装するなら「意味を持たせる」
か「エラーにする」かの判断が要る。

## 別枠: 浮動小数点 (float / double)

絶対量では最大の欠落 (型の語彙にまるごと無い)。
やるなら型・演算・変換・FP レジスタの呼び出し
規約まで一貫した大工事。ただし実需は当面なく、
デコーダは固定小数点、nami は整数だけ、ツール
チェーンも整数で完結している。OS 側の受け口
(FPU 有効化と fcsr 初期化) は用意済みなので、
やるなら iwac 側だけの仕事になる。実需が出た
ときに独立した大版として設計から。

## 欠落ではないもの (意図的な対象外)

- #include、関数マクロ、#if の式: 複数ファイル
  連結と単純な #define / #ifdef で代替する
  設計判断。対象外として置く

## 既に揃っている基本 (参考)

if / else、while、for、三項演算子、break /
continue、複合代入、++/--、キャスト (幅つき型
への変換は本物)、typedef、構造体 (基本形)、
2 次元までの配列、ファイル範囲の配列初期化子、
ポインタとアドレス演算、再帰呼び出し。

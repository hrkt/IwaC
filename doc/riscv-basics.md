# iwac の第3層を読むための RISC-V メモ

この文書は、第3層（encode: 命令列を機械語に変える層）を
読むための前提知識をまとめたもの。コンパイラの設計は
doc/design.md、命令の一覧は KosabaOS 側の早見表
（arch/riscv64/instructions.md）が担当で、ここは
「命令の形と、値の扱い」の概念を置く。

## 1. 命令は「小さな申告書」

RISC-V の命令は1つが32ビット。その中は区画（フィールド）
に分かれていて、「何をするか」だけでなく「宛先はどこか」
「材料は何か」「値そのもの」まで全部が詰まっている。

例: `addi t1, zero, 65`（t1 に 65 を入れる）は
0x04100313 という32ビットになる:

```
区画:   [ imm=65 ][ rs1=0 ][ funct3=0 ][ rd=6 ][ opcode=0x13 ]
ビット:   31..20     19..15     14..12     11..7      6..0
```

- rd = 6: 宛先は「t1（= x6）番レジスタ」という番号指定
- rs1 = 0: 材料は「zero（x0、常に0）番レジスタの中身」
- imm = 65: 値そのもの（I 形式では12ビットの符号付き数）
- opcode と funct3: 「レジスタと即値を足して rd へ」という
  種類の指定

区画の並び（形式）はいくつかあり、iwac が使うのは主に:

- R 形式: 材料はレジスタ2つ（add、mul など）。
  imm の場所にもう1つのレジスタ番号 rs2 が入る
- I 形式: 材料はレジスタ1つと即値（addi、lbu、ld、jalr）
- U 形式: 大きな即値の上の方20ビット（lui、auipc）
- S 形式: メモリへ書く（sb、sd）。即値は上下に分かれて入る
- B 形式: 条件分岐（beq）。飛び先のビットが散らばって入る
- J 形式: ジャンプ（jal）。B 形式とは散らばり方が違う

「値を持ち込む」か「値の入ったレジスタを指定するか」で、
同じビット位置の使い道が変わるのが形式という考え方。

## 2. 値はどうやってレジスタへ運ぶか

命令自体が32ビットしかないので、32ビットや64ビットの
値を丸ごと1命令には載せられない（載せたら「何をする
命令か」を書く場所が残らない）。運び方は3通り:

- **小さい値は即値で**: I 形式の即値は12ビット符号付き
  （-2048〜2047）。文字コードなどは addi 一発で入る
- **組み立てる**: 32ビットの値なら lui（上の20ビット）
  ＋ addi（下の12ビット）の2命令。64ビットなら
  lui → addiw → slli（ずらす）→ addi → …と継ぎ足して
  最大8命令ほど。アセンブリの `li` はこの連鎖に展開
  される疑似命令（見かけは1命令）。
  注意: addi の即値は符号拡張される。下12ビットが
  0x800 以上だと負の数として引かれるので、上の側に
  あらかじめ1を足しておく調整が要る。iwac は住所を
  0x8020xxxx に置こうとして実際にこの罠にかかり、
  絶対住所（lui + addi）をやめて相対住所
  （auipc + addi）に切り替えた（v3 の学び）
- **メモリから読む**: 定数をデータとしてバイナリに
  置いておき、住所を作って ld で読む。値の大きさに
  制限はない。文字列はこの方式のバイト版で、iwac は
  コードの後ろに文字列を並べ（str_pool）、lbu で
  1バイトずつ読む

どの運び方にするかはコンパイラ側の判断で、iwac では
第2層が (op, rd, rs1, rs2, imm) の組として形を決める。

## 3. レジスタに乗る値

RV64 のレジスタ（x0〜x31）は64ビットの箱で、中身の
ビット列に型は無い。何の値かは使う側の解釈で決まる:

- **数**: 計算の材料と結果。文字もこの仲間で、'A' は
  数として 65。符号あり/なしも箱には記録されず、
  命令側の解釈次第（slt と sltu、lb と lbu の違い）
- **住所**: 実は主役級。sp（x2）はスタックの現在位置、
  ra（x1）は戻り先のコードの住所。文字列や配列は
  中身が箱に入らず、先頭の住所だけが乗る。
  装置の窓口の住所（MMIO）もこの仲間で、iwac では
  t0 に UART の住所 0x10000000 が常駐し、ここへ
  1バイト書くとシリアルに文字が出る
- **真偽**: 比較命令の結果として 0 か 1。
  if や while の条件はこの形
- **x0（zero）だけ特別**: 常に 0 で、何を書いても
  0 のまま。捨てたい結果の宛先や、0 を材料にする
  ときに使う

乗らないもの: 小数（浮動小数点）は別のレジスタ群
（f0〜f31）の担当。RV64G にはその仕組みも含まれるが、
iwac は使っていない。文字列や配列そのもの全体も
乗らない（入るのは住所だけ）。

iwac の生成コードでのレジスタの約束（src/01-head.c）:

- t0（x5）: UART の住所（ベアメタル版のみ）
- t1（x6）: 「今の値」— 式の評価結果はここに置く
- t2（x7）: 次の項・作業用
- t3〜t6（x28〜x31）: 変数（最大4個。v21 でメモリ化予定）
- a0（x10）: 関数の引数。OS 版ではシステムコールの
  引数と戻り値にも使う
- a7（x17）: OS 版のシステムコール番号
- ra（x1）: 戻り先の住所、sp（x2）: スタック

## 4. iwac の中での対応

第2層の命令列は、並行配列 asm_op[] / asm_rd[] /
asm_rs1[] / asm_rs2[] / asm_imm[] に「番号ごとの行」
として並んでいる。第3層の encode_inst(i) の引数は
命令そのものでなく**命令列の中の番号**で、関数の中で
その行の材料を全部引き出してから、形式に合わせて
32ビットに詰めて返す。分岐（beq）とジャンプ（jal）
だけは、飛び先も命令番号で持っているので、
(飛び先番号 - 自分の番号) × 4 でバイト単位の相対
オフセットに直してから詰める。

# IwaC 進捗（できていること）

## 2026-11-01: 構造整理 — 内部を3層に分離（AST／命令列／符号化）

- ユーザーの希望: 直接バイナリを出す方針は良い。その上で、
  バイナリを書く部分、アセンブラ的に機械語一歩手前にする
  部分、ソースを構文解析して AST にする部分を、
  分かりやすく分けておいてほしい
- やったこと（言語仕様は不変、内部の再構成のみ）:
  - 第1層 parse: ソース → AST（抽象構文木）。
    `65+1` は「`+` を根、左 65、右 1」の木。ノードは
    構造体・ポインタ・malloc を使わず、4本の並行配列
    （種類・値・左・右）とノード番号で表現した
  - 第2層 gen: AST → 命令列。命令は「種類・rd・rs1・rs2・
    即値」の組の配列として持ち、アセンブリ文字列にはしない。
    この層はビット列を知らない
  - 第3層 encode: 命令列 → 32ビット機械語 → 出力。
    ビット配置の知識はこの層だけが持つ（各命令の式に
    フィールド図のコメント付き）
  - main は parse → gen → write を順に呼ぶだけになった
- 検証:
  - gcc ビルド警告なし、プリプロセッサ行ゼロ
  - 正常系10ケース（`A`、`65`、`B`、`65+1`、`66-1`、
    `50+10+5`、`65 + 1`、`2000+2000`、`1-2-3`、`100-200`）
    の出力バイナリが、整理前のビルドと**全て完全一致**
  - `65+1` の逆アセンブルも従来通り（6命令）
  - エラー系も従来通り（終了コード1、標準出力0バイト）
  - `./test.sh` の QEMU 実行確認も含めて PASS（下記コミット時点）


## 2026-11-01: 修正 — iwac.c からプリプロセッサを全廃

- ユーザーの指摘: 「`#include <stdio.h>` とか、まだ作って
  いないよね？」その通りで、iwac 自身のソースが、iwac の
  言語に無いものを使っていた。方針として明文化した
  （`doc/design.md` 6章、`doc/notes.md`）
- やったこと:
  - `#include` を全廃。使う外部関数は `write` だけで、
    その宣言を自分で書く（ヘッダなし）
  - `#define` も廃止（項数上限の 256 は直接書く）
  - `fprintf` / `exit` をやめ、エラーは戻り値で伝えて
    main が `write` で標準エラー出力に表示する形に変更
  - `putchar` をやめ、出力は `write` を呼ぶ `out_byte` に変更
  - 理由と仕組みは `iwac.c` 冒頭のコメントに厚く書いた
- 検証:
  - プリプロセッサ行がソースに0行であることを grep で確認
  - gcc ビルドは警告なし
  - 正常系8ケース（`A`、`65`、`B`、`65+1`、`66-1`、
    `50+10+5`、`65 + 1`、`2000+2000`）の出力バイナリが
    修正前と**バイト単位で完全一致**
  - エラー系4ケースも従来通り（終了コード1、標準出力0バイト、
    メッセージ同一）


## 2026-11-01: v1 — 式（足し算・引き算）

- 言語が育った: 数字と `+` / `-` の式を受け取れるようにした
  （文法は `iwac.c` 冒頭と `doc/roadmap.md` の v1 の項）
  - 例: `65+1` → `B`、`66-1` → `A`、`50+10+5` → `A`
  - 空白を挟んでもよい。v0 の「1文字 / 数字だけ」も互換で動作
- 実装の要点:
  - 計算はコンパイラが代行せず、出力バイナリの中の `add` /
    `sub` 命令が実行時に行う（v1 の核心）
  - parse（項と演算子の配列化）と codegen（機械語生成）を分離。
    解析が全部終わるまで出力しないので、文法エラーでは
    バイナリが1バイトも出ない
  - 項の上限は 2047（`addi` の即値が符号付き12ビットのため。
    超えたらエラー）。途中経過と結果は64ビットレジスタの中の
    出来事なので上限なしで、UART には最後に下1バイトが出る
- 検証（`./test.sh` で再現できる内容。QEMU 実行は計5ケース）:
  - v0 互換: `A` の出力バイナリが v0 版とバイト単位で一致（16バイト）
  - `65+1` は24バイト、逆アセンブルが
    `lui t0` / `li t1,65` / `li t2,1` / `add t1,t1,t2` / `sb` / `wfi`
    の想定通り
  - QEMU 実行: `65+1` → `B`、`66-1` → `A`、`50+10+5` → `A`、
    参考に手元確認した `2000+2000` → 下1バイト 0xA0
  - 空白あり (`65 + 1`) が空白なしと同じバイナリになった
  - エラー確認: `65+`、`65*2`、`2048`、空文字列のいずれも
    終了コード1で失敗し、標準出力は0バイトだった
- 次は v2: 式の続き（`*` / `/` とかっこ、演算子の優先順位）

# IwaC 進捗（できていること）

## 2026-11-01: v1 — 式（足し算・引き算）

- 言語が育った: 数字と `+` / `-` の式を受け取れるようにした
  （文法は `iwac.c` 冒頭と `doc/roadmap.md` の v1 の項）
  - 例: `65+1` → `B`、`66-1` → `A`、`50+10+5` → `A`
  - 空白を挟んでもよい。v0 の「1文字 / 数字だけ」も互換で動作
- 実装の要点:
  - 計算はコンパイラが代行せず、出力バイナリの中の `add` /
    `sub` 命令が実行時に行う（v1 の核心）
  - parse（項と演算子の配列化）と codegen（機械語生成）を分離。
    解析が全部終わるまで出力しないので、文法エラーでは
    バイナリが1バイトも出ない
  - 項の上限は 2047（`addi` の即値が符号付き12ビットのため。
    超えたらエラー）。途中経過と結果は64ビットレジスタの中の
    出来事なので上限なしで、UART には最後に下1バイトが出る
- 検証（`./test.sh` で再現できる内容。QEMU 実行は計5ケース）:
  - v0 互換: `A` の出力バイナリが v0 版とバイト単位で一致（16バイト）
  - `65+1` は24バイト、逆アセンブルが
    `lui t0` / `li t1,65` / `li t2,1` / `add t1,t1,t2` / `sb` / `wfi`
    の想定通り
  - QEMU 実行: `65+1` → `B`、`66-1` → `A`、`50+10+5` → `A`、
    参考に手元確認した `2000+2000` → 下1バイト 0xA0
  - 空白あり (`65 + 1`) が空白なしと同じバイナリになった
  - エラー確認: `65+`、`65*2`、`2048`、空文字列のいずれも
    終了コード1で失敗し、標準出力は0バイトだった
- 次は v2: 式の続き（`*` / `/` とかっこ、演算子の優先順位）

## 2026-11-01: v0 — 一番小さいバイナリが出て、動いた

- リポジトリを用意した: `~/workspace/iwac/iwac/`
  （GitHub は https://github.com/hrkt/IwaC ）
  ワークスペースの構成と理由は `doc/environment.md`
- `iwac.c` v0 を実装（当面は1ファイル）:
  - 入力は引数で渡すプログラム文字列: 1文字、または 10進数 0..255
  - 出力は RISC-V (rv64i) 生バイナリ 16バイト、命令4つ
    （`lui t0,0x10000` / `addi t1,zero,code` / `sb t1,0(t0)` / `wfi`）
  - UART (NS16550A、ベース `0x10000000`) へ1バイト書いて止まる
- 検証（`./test.sh` で再現できる内容）:
  - gcc 13.3.0 で警告なしビルド
  - `iwac A` と `iwac 65` の出力がバイト単位で一致、サイズは16
  - 逆アセンブルが想定の4命令と一致
    （`lui t0,0x10000` / `li t1,65` / `sb t1,0(t0)` / `wfi`）
  - QEMU virt で実行し、シリアルログの最後の1バイトが
    入力通り `A` / `B` になった。A用とB用のログは
    その最後の1バイトだけが違った（OpenSBI の表示部分は同一）
    ＝ 出ている文字が本当にこのバイナリ由来だと確認できた
- GitHub へ push 済み（IwaC専用のデプロイキーを登録後）。
  リモート main がローカルと一致することを検証済み
- 未確認・意図的にやっていないこと:
  - UART 送信ポーリング無し（QEMU での第一歩として省略。実機向けの課題）
  - UART 初期化（分周比など）無し（同上、QEMU のデフォルトで動作）

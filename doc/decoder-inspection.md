# デコーダ再点検の記録 (2026-11-24、v61 実機結果を受けて)

v61 ビルドの nami で FREE128 の under が 746,816 → 4,672
まで減ったが、ユーザーの耳では「ポールのパートでダメ」
と最密度区間に欠けが残った。区間固有の hotspot が
デコーダにあるのかを点検した記録。結論を先に:

**区間固有の hotspot は無い。残りは曲全体の余裕が
ほぼゼロという問題で、数 % の底上げが全体に効けば
決着するはず (実際 −22.5% で under が −99.4% に
なったのがその形)。**

## 計測 1: 区間ごとの段別コスト (icount)

FREE128 から 770 フレーム (約 20 秒) の抜粋を 3 つ
切り、PERFSTG (v61 ビルド) を QEMU icount で回した。
抜粋の開始は main_data_begin が小さいフレームに
合わせ、計測 TU だけリザーバ帳簿の初回チェックを
緩めた (履歴ぶんをゼロで追加したことにする。
初回フレームのスペクトルだけ化けるが、コスト計測
には影響しない)。

フレームあたり (icount の拡大単位、770 フレーム平均):

| 抜粋 | 段3まで | 段4 | 段5 | 合計 |
|---|---|---|---|---|
| A 序盤 (5〜25 秒) | 32.3M | 48.8M | 97.6M | 178.7M |
| B 135〜155 秒 | 33.0M | 49.2M | 97.6M | 179.8M |
| C 194〜214 秒 | 33.1M | 49.4M | 97.6M | 180.1M |

- 段5 は全区間完全一致 (97.6M)。ソースどおり合成は
  密度に依存しない固定費。
- 段3までは後半 +2.4% (ハフマンと再量子化が密度に
  少し追従)、段4 は +1.2%。合計の広がりは +0.8%。
- ホスト側のフレーム別プロファイル (時間と非ゼロ数、
  側情報の p23 / big_values / block_type) でも同じ:
  差は数 % 以内。序盤だけ非ゼロ率が 57% と低い
  (静かな入りと Xing) ため、再生開始直後は余裕が
  できやすい、という程度。

つまりポールのパートが崩れるのは、その区間だけ
特別に重いのではなく、全体が実時間の線の上に
乗っていて、リングバッファ (約 186ms) が
ジッタや読み出しの揺れを吸収しきれない所から
欠け始める、と読むのが自然。

## 計測 2: 生成コードの点検 (段5 の 2 つの内側ループ)

v61 ビルドの nami 逆アセンブルで synth_granule の
最内ループを数えた。

- 行列ループ (MAC 1 回): 約 27 命令。実仕事は
  lw + ld + mul + add の 4。残りは synth_cos_q30 の
  アドレス再組み立て (auipc 対 + row*32 + k が
  MAC ごと)、dpv/cmv の添字計算、acc の保持往復。
- tau ループ (タップ 1 回): 約 22 命令。実仕事は
  約 4。v_hist アドレスの組み立てが 2 系統
  (synth_d と synth_row) でレジスタが衝突し、
  **ループの中でスタックへ退避・復帰が 1 往復**
  入っている。slot もレジスタに無く、タップごとに
  メモリから 2 回読み直している。
- 同じ形のループを単独で切り出した再現コードでは、
  レジスタに空きがあるため歩くポインタ (v57) が
  効いて約 19 命令/MAC まで落ちる。

つまり v57 の歩くポインタも v61 の直接更新も、
synth_granule では **s レジスタ 11 本を使い切って
いて発火できない**。v_hist 基底アドレスの件も
含め、段5 の残りの太りは「レジスタ圧」という
1 つの原因に帰着する。

## デコーダ側の候補 (nami 側の仕事、ビット不変)

効果の大きい順。どれも数 % 級で、決め手ではない。

1. tau ループの synth_row を差分テーブル化し、
   v_hist アドレスを歩くポインタにする。タップ
   ごとに約 2 命令、段5 で −2〜3%。2 つのランへの
   分割点のジャンプも、di が連続なので差分テーブル
   側に畳める。
2. PCM ストアの添字 (gr*576 + t*32 + m)*nch + ch を
   歩くポインタに。1% 未満だが確実。
3. antialias のゼロバンドスキップ (両側ゼロの
   境界だけ飛ばす)。軽い区間にしか効かない。
   平均の底上げにはなるが最密度区間は救わない。
4. 周波数反転の sat32(-x) は、xr の値域の証明が
   できれば素の否定にできる。効果小、証明が要る。
5. sb の gather (stride 18) の歩くポインタ化。
   0.2% 級。

## コンパイラ側の候補 (こちらが本命)

レジスタ圧の緩和が次の大きな段。候補の形:

- 生存区間の分割: 内側ループの間だけ変数の
  レジスタを解放し、前後で退避・復帰する。
- 呼び出しの無いループ内に限り、t レジスタ
  (t3〜t6) をループ変数の置き場に使う。
- どちらも「synth_granule で歩くポインタと
  直接更新が発火できる状態を作る」のが目的。

行列と tau の両ループが 25 命令級から 15 命令級に
落ちれば、段5 で −25〜35%、全体で −15〜20% に
なり、実曲の余裕としては十分なはず。
